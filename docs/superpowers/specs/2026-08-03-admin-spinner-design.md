# 어드민 돌림판 설계

## 범위

- 어드민 사이드바에 기본 접힘 상태의 `편의` 그룹과 `돌림판` 메뉴를 추가한다.
- `/admin/spinner`에서 후보를 관리하고, 애니메이션으로 한 항목을 추첨한다.
- 새로고침 복구만 필요하므로 후보 목록과 옵션은 브라우저 `sessionStorage`에만 저장한다. 서버 저장·당첨 이력·공유 기능은 범위 밖이다.

## 데이터와 후보 추가

- 서버 페이지에서 활동 상태이면서 승인된 회원의 `id`, `name`, `position`만 가져와 클라이언트에 전달한다.
- `전체 회원`, `프론트엔드`, `백엔드`, `디자이너`, `비기너` 버튼은 조건에 맞는 회원 이름을 후보에 추가한다.
- 직접 입력으로 임의 항목을 하나씩 추가할 수 있다.
- 같은 표시명은 중복 추가하지 않는다. 일괄 추가 뒤 이미 포함된 후보는 건너뛴다.

## 화면과 동작

- 데스크톱은 왼쪽 룰렛, 오른쪽 후보 관리 패널의 두 열 레이아웃이며 좁은 화면에서는 세로로 쌓는다.
- 룰렛은 기존 색상 토큰을 사용한 균등 조각과 상단 고정 포인터로 표현한다. 후보가 없으면 안내 상태를 보여준다.
- 시작 버튼은 후보가 있을 때만 활성화한다. 추첨 중에는 입력과 변경 버튼을 비활성화한다.
- 룰렛은 CSS `transform` 전환으로 여러 바퀴 회전한 뒤 선택된 조각에서 멈춘다. `prefers-reduced-motion`에서는 즉시 결과를 표시한다.
- 결과는 화면에 명확히 표시한다. `당첨 후 후보에서 제거` 토글이 켜져 있으면 애니메이션 완료 후 해당 후보를 제거한다.
- 후보 행별 삭제와 전체 초기화 버튼을 둔다.

## 구현 경계

- 인터랙션과 `sessionStorage`는 좁은 클라이언트 컴포넌트에 둔다. 인증과 회원 조회는 서버 페이지가 담당한다.
- 기존 `PageHeader`, `Card`, `Button`, `Input`과 Tailwind 유틸리티를 사용한다. 애니메이션 라이브러리나 새 의존성은 추가하지 않는다.
- 후보 상태와 제거 토글을 한 `sessionStorage` 키의 JSON으로 저장한다. 잘못된 저장값은 무시하고 빈 상태로 시작한다.

## 검증

- 일괄 추가 대상(승인·활동·포지션) 필터와 중복 제거를 단위 테스트한다.
- `pnpm typecheck:admin`과 관련 테스트를 실행한다.
