# 도감 전투 선공 및 턴제 설계

## 목표

친선전과 랭킹전 모두 서버가 공정하게 동전을 한 번 던져 선공을 정하고, 같은 HP·피해 규칙의 교대 턴 전투를 재생한다. 브라우저는 확정된 결과만 표시하며 전투 결과에 영향을 주지 않는다.

## 공통 전투 규칙

- 전투 시작 시 서버가 동전을 한 번 던져 선공 사용자를 확정한다.
- 포켓몬 최대 HP는 `1,000 + 전투력`이다.
- 피해는 `(200 + 전투력 × 0.4) × 타입 보정 × 단일 타입 보정 × 95~105%`로 계산한다.
- 타입 보정은 유리 `1.2`, 불리 `0.8`, 그 외 `1.0`이며, 단일 타입 덱 보너스는 기존 랭킹전 규칙대로 `1.1`이다. 친선전의 한 마리 파티도 이 규칙을 그대로 적용한다.
- 선공부터 한 번씩 번갈아 공격한다. 대상의 HP가 0이 되면 그 공격으로 끝나며 반격은 없다.
- 공격 순서는 교체로 초기화되지 않는다. 쓰러진 랭킹전 포켓몬은 다음 포켓몬으로 교체되고, 원래 다음 차례가 이어진다.
- 모든 난수, 피해, HP, 승패는 한 서버 트랜잭션 안에서 계산·저장한다.

## 친선전

- 신청자와 수락자가 각각 한 마리로 전투한다.
- 수락 RPC가 선공, 공격 로그, 승자를 확정한다. 기존의 전투력 점수 비교와 동점 추첨은 새 결투에 사용하지 않는다.
- 새 결투는 타입 상성과 피해 난수를 포함한 공통 전투 규칙을 사용한다.

## 랭킹전

- 일일 배정에서 정해진 공격자·방어자 역할과 점수 증감은 유지한다.
- 전투 시작 RPC가 한 번만 동전을 던져 최초 선공을 정한다. 포켓몬 교체 시 다시 던지지 않는다.
- 공격·교체·HP·승패가 끝날 때까지 전투 전체를 원자적으로 확정한다.

## 기록과 호환성

- 새 친선 결투와 랭킹전 기록에 `first_turn_user_id` 및 공격 단위 `battle_log`를 저장한다. 각 로그에는 공격 측, 양측 활성 포켓몬 인덱스, 피해, 공격 후 양측 HP를 담는다.
- 친선전의 기존 점수 컬럼은 과거 데이터 호환을 위해 유지한다. 새 결투의 승패 계산에는 사용하지 않는다.
- 새 형식의 전투 기록은 동전 결과와 전투 전체를 재생한다. 기존 랭킹전 기록은 기존 표 형식으로 유지하고, 새 연출로 변환하지 않는다.

## 화면과 연출

- 전투 모달은 포켓몬 등장 전에 CSS 동전을 회전시킨다. 친선전 신청자/랭킹전 공격자가 앞면, 상대/방어자가 뒷면이다.
- 동전이 멈추면 선공자를 명확히 표시하고, 저장된 공격 로그를 공격 → HP 갱신 → 쓰러짐 → 교체 순으로 재생한다.
- 다시 보기와 새 형식의 과거 전투 상세도 동일한 저장 결과를 재생한다.
- `prefers-reduced-motion`에서는 동전을 회전시키지 않고 결과를 즉시 표시한다.
- 새 이미지 자산이나 외부 의존성은 추가하지 않는다.

## 검증

- 서버 테스트는 동전이 전투당 한 번만 결정되는지, 선공부터 순서대로 교대하는지, HP가 음수가 되지 않는지, 쓰러진 포켓몬이 공격하지 않는지 검증한다.
- 친선전과 랭킹전이 공통 피해식·타입 보정을 쓰는지 검증한다.
- UI 테스트는 저장된 동전 결과를 재생하고, 모션 감소 환경에서 즉시 표시하며, 기존 랭킹전 기록이 기존 표시로 남는지 검증한다.
