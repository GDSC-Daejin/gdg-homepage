# 모지숲 AI 안건 초안 — 설계

> 상태: 보류 — LLM 런타임 인증을 추가할 때 구현한다.

## 목표

모지숲 일정이 확정되면 기존 노션 위클리 템플릿을 만든 뒤, 전주 회의의 안건·결정사항과
그 이후 어드민 Slack 채널 대화를 바탕으로 이번 회의의 **AI 초안 안건**을 같은 노션 페이지에
추가한다. 운영진은 회의 전에 초안을 수정·삭제해 최종 안건으로 만든다.

일반 일정은 이 기능의 대상이 아니다. 현재의 일반 일정 확정 DM 흐름도 바꾸지 않는다.

## 전제

- `SLACK_JARVIS_BOT_TOKEN`은 프라이빗 어드민 채널의 `groups:history` 권한을 이미 가지며,
  Jarvis는 해당 채널의 멤버다.
- 모델 제공자 인증은 현재 없다. 구현 시 `ANTHROPIC_API_KEY` 또는 동등한 서버 전용
  LLM 게이트웨이 인증을 배포 환경변수로 등록한다.
- 인증이 없으면 현행처럼 노션 위클리 템플릿만 만들고, 안건 생성은 조용히 건너뛴다.

## 확정 흐름

1. `meeting_polls.is_mojisoop = true`인 일정만 기존 `createWeeklyPage`로 노션 위클리
   템플릿 페이지를 생성한다.
2. 새 회의 날짜보다 이른 가장 최근 위클리 페이지를 찾아, 페이지 본문의 `안건`과
   `결정사항` 블록 텍스트를 읽는다. 이전 페이지가 없으면 이 입력은 빈 값이다.
3. Slack `conversations.history`로 이전 회의 시각 이후부터 새 일정 확정 시각 전까지의
   어드민 채널 메시지를 읽는다. 최근순 응답을 시간순으로 뒤집고, 메시지는 최대 200개만
   사용한다. 스레드 답글은 이번 범위에서 읽지 않는다.
4. 모델에는 이전 회의 텍스트와 Slack 원문만 전달한다. 다음 세 섹션을 한국어 Markdown으로
   반환하게 한다.
   - `지난 결정사항 후속`: 완료·보류·확인이 필요한 항목
   - `이번 회의 안건`: 논의 주제와 근거를 짧게 묶은 목록
   - `결정이 필요한 항목`: 결정 주체 또는 선택지가 있는 항목
5. 노션 페이지 본문 끝에 `AI 초안 안건` 제목과 모델 결과를 블록으로 append한다. 템플릿의
   기존 내용은 수정·삭제하지 않는다.
6. 운영진은 노션에서 초안을 자유롭게 편집한다. 사이트에는 초안 편집 화면이나 승인 상태를
   만들지 않는다.

## 데이터·보안 경계

- Slack 원문, 전주 회의 본문, 프롬프트·응답은 Supabase에 저장하지 않는다.
- 모델 호출은 서버에서만 한다. API 키와 Slack·Notion 토큰은 클라이언트 번들에 포함하지
  않는다.
- AI 제공자에게 보내는 데이터는 프라이빗 운영 대화임을 전제로 한다. 키를 도입할 때
  제공자의 데이터 보존·학습 정책을 운영진이 확인한다.
- Notion 페이지 생성과 AI 초안 생성은 분리한다. AI 호출 실패가 일정 확정이나 템플릿
  생성을 되돌리면 안 된다.

## 실패 처리

| 상황 | 처리 |
| --- | --- |
| LLM 인증 미설정 | 템플릿만 생성하고 기존 확정 성공 흐름을 유지 |
| 전주 회의 없음 | Slack 대화만으로 초안 생성 |
| Slack 읽기 실패 | 전주 회의 내용만으로 초안 생성 |
| LLM 호출 또는 노션 append 실패 | 템플릿 생성은 유지하고 어드민 확정 화면에 경고 표시 |
| 노션 템플릿 생성 실패 | 기존과 같이 확정은 유지하고 노션 생성 실패를 경고 |

## 기존 설계와의 관계

`2026-07-19-mojisup-meeting-notes-design.md`의 기본 원칙(노션이 source of truth,
사이트는 회의록을 편집하지 않음)은 유지한다. 이 설계는 사이트가 회의록을 최종 작성하는
기능이 아니라, 노션 템플릿에 운영진 검토용 초안을 추가하는 예외다. 노션 템플릿의 정기
안건·relation·이월 안건 자리는 계속 유지한다.

## 제외

- 일반 일정의 노션 페이지·AI 안건 생성
- Slack 스레드, 파일, DM, 다른 채널 읽기
- AI 결과의 자동 확정 또는 Member 공개
- Slack 원문·AI 결과의 별도 데이터베이스 보관
- API 키가 없는 상태의 대체 자동화
