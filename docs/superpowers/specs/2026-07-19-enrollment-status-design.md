# 재학 여부 관리 설계

## 목적

회원의 재학 여부를 `재학`, `휴학`, `졸업`으로 관리한다. 회원 관리, 회원 프로필, 온보딩, 공개 지원서에서 같은 선택지를 사용한다.

## 데이터

- `profiles.enrollment_status`와 `applications.enrollment_status`에 각각 텍스트 상태를 저장한다.
- 허용값은 `enrolled`, `leave_of_absence`, `graduated`이다.
- 두 컬럼은 `not null`이며 기본값은 `enrolled`이다. 기존 행도 마이그레이션으로 `enrolled`가 적용된다.
- 공개 지원서는 익명 데이터이므로 지원서 값과 회원 프로필 값을 자동으로 연결하지 않는다.

## 사용자 흐름

- 온보딩과 내 프로필 수정에 필수 선택 항목 `재학 여부`를 추가한다.
- 공개 지원서에도 같은 필수 선택 항목을 추가하고, 제출 시 `applications`에 저장한다.
- 서버 스키마에서 세 값만 허용하도록 검증한다.

## 관리자 흐름

- 회원 관리 테이블에 `재학 여부` 열을 표시한다.
- 기존 회원 프로필 수정 모달과 상세 페이지의 프로필 수정 폼에서 재학 여부를 수정한다.
- 기존 관리자 프로필 수정 RPC에 해당 인자를 추가해 변경한다.

## 검증

- 프로필 및 지원서 스키마가 유효한 재학 여부만 허용하는 단위 테스트를 둔다.
- TypeScript 타입 검사를 실행한다.
