# 도감 랭킹전 사전 안내 설계

## 목표

랭킹전이 열리기 전까지 회원용 `랭킹전` 탭을 친절한 3:3 대결 튜토리얼로 대체한다. 회원이 포켓몬을 모으는 동안 규칙과 준비 순서를 이해할 수 있게 하며, 운영자가 오픈을 지시할 때 한 곳만 바꿔 기존 랭킹전을 다시 연다.

## 범위

- `src/app/(member)/pokedex/page.tsx`에 `RANKING_LEAGUE_OPEN = false`를 둔다.
- 값이 `false`일 때 회원용 랭킹 탭에는 `추후 오픈 예정` 헤더와 사전 안내만 보인다.
- 헤더에는 피카츄 이미지, 네 개의 규칙 카드에는 포켓몬 이미지를 사용한다. 기존 PokeAPI 스프라이트 사용 방식을 따른다.
- 카드 순서는 다음과 같다.
  1. 서로 다른 포켓몬 6종을 모아 참가한다.
  2. 공격·방어 팀을 각각 구성한다. 팀은 서로 다른 3마리이며 전설·환상은 한 마리까지다.
  3. 하루 3회 공격할 수 있고 상대는 매일 오전 6시에 갱신된다. 첫 전투 전 하루 한 번 상대를 바꿀 수 있다.
  4. 전투력·타입 상성과 같은 타입 팀 보너스로 승부한다. 공격 승패 점수와 방어 성공 점수를 설명한다.
- 방어 팀 변경은 다음 날 오전 6시부터 매칭에 반영된다는 보조 규칙을 점수 안내 아래에 둔다.
- 데스크톱에서는 두 열 카드, 좁은 화면에서는 한 열 카드로 배치한다. 카드 제목 영역·본문 시작선·포켓몬 위치를 통일하고, 포켓몬은 본문 높이에 맞춰 크게 배치한다.
- 제목·본문·보조 규칙에 서로 다른 글자 크기, 행간, 자간을 적용한다. 한국어 문장은 의미 단위로 줄바꿈하고 `keep-all`·`break-word` 규칙을 유지한다.
- `false`일 때 `pokedex_rank_state` RPC를 호출하지 않는다. 따라서 랭킹 시즌·참가 상태를 읽거나 생성하지 않는다.
- 관리자 포켓몬 개발 탭의 `RankingLeaguePreview`, 기존 서버 액션·마이그레이션·`RankingLeaguePanel`은 변경하지 않는다.

## 제외

- 운영자 화면이나 원격 설정 화면을 만들지 않는다.
- 랭킹전 규칙, 점수, 서버 액션, 데이터베이스를 바꾸지 않는다.
- 새 이미지 파일·의존성을 추가하지 않는다.

## 검증

- 랭킹전 페이지 테스트가 닫힌 상태의 안내·토글·RPC 차단을 검증한다.
- `pnpm test tests/pokedex-ranking-page.test.ts`와 `pnpm typecheck:v1`을 실행한다.

## 오픈 방법

운영자가 오픈을 지시하면 `RANKING_LEAGUE_OPEN`만 `true`로 변경한다. 기존 `RankingLeaguePanel`과 서버 랭킹 흐름이 다시 표시된다.
