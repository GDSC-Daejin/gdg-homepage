# 장소 상세·리뷰 — 설계

- 작성일: 2026-07-20
- 대상 화면: 회원 이벤트 상세 `/events/[id]`, 관리자 장소 `/admin/places`

## 목표

이벤트 상세의 지도 아래에서 우리 서비스가 관리하는 장소 정보를 확인하고, 멤버가 별점과 짧은 후기를 남긴다. 장소 기본 정보는 관리자만 관리하며, 리뷰 삭제는 관리자 승인으로만 처리한다.

## 범위

### 장소 기본 정보

`places`에 다음 선택 필드를 추가한다.

- `phone`
- `hours`
- `website`
- `amenities`
- `description`

관리자는 기존 `/admin/places` 화면에서 이 정보를 추가·수정한다. 지도 좌표, 장소명, 주소 관리 흐름은 유지한다.

### 멤버 리뷰

`place_reviews` 테이블을 추가한다.

- 장소·작성자별 리뷰는 하나만 허용한다.
- `rating`은 1~5점, `body`는 짧은 후기다.
- 로그인한 멤버는 자신의 리뷰를 생성·수정할 수 있고, 모든 멤버는 공개 리뷰를 읽을 수 있다.
- 멤버의 삭제 요청은 `delete_requested_at`만 기록한다. 실제 삭제와 요청 반려는 관리자만 할 수 있다.
- 관리자도 일반 멤버와 동일하게 리뷰를 작성·수정할 수 있다.

### 회원 이벤트 상세

이벤트에 연결된 `place`가 있으면 지도 아래에 장소 상세 패널을 표시한다.

1. 장소명, 주소, 전화번호, 운영시간, 웹사이트, 편의시설, 소개를 값이 있는 항목만 표시한다.
2. 리뷰 평균과 리뷰 수를 표시한다.
3. 멤버는 별점과 후기 작성·수정 폼을 사용한다.
4. 리뷰 목록에는 작성자, 별점, 후기, 작성 시각을 표시한다.
5. 삭제 요청이 남은 자신의 리뷰에는 요청 상태를 표시한다.

과거처럼 `place_id`가 없는 이벤트는 장소 상세·리뷰를 표시하지 않고, 기존 장소 텍스트와 지도만 유지한다.

### 관리자 장소 대시보드

새 경로를 만들지 않고 기존 `/admin/places` 상단에 다음 요약을 둔다.

- 전체 장소 수
- 전체 리뷰 수
- 삭제 요청 수

각 장소 행에는 평균 별점·리뷰 수·삭제 요청 여부를 함께 보여준다. 관리자는 요청된 리뷰를 삭제하거나 요청을 반려한다.

## 데이터 및 권한

`place_reviews`는 `place_id`와 `user_id`의 복합 유니크 제약, 별점 범위 제약을 둔다. RLS는 인증된 사용자의 읽기를 허용하고, 본인 리뷰의 생성·수정만 허용한다. 삭제 권한은 관리자에게만 부여한다. 장소 기본 정보의 쓰기 권한은 기존처럼 관리자만 가진다.

## 화면 규칙

- 네이버 앱·웹으로 이동하는 버튼과 딥링크는 추가하지 않는다.
- 첨부한 네이버 지도 화면의 정보 위계만 참고한다. 사진·리뷰·영업정보를 외부에서 가져오거나 네이버 UI를 복제하지 않는다.
- 현재 `Card`, `Badge`, `Button`, `Input`, `Textarea`와 기존 색상 토큰을 사용한다.
- 모바일에서는 장소 상세와 리뷰를 한 열로 쌓는다.

## 검증

- 마이그레이션과 타입에 새 필드·제약이 반영된다.
- 멤버가 리뷰를 작성·수정하고 삭제 요청을 남기는 서버 액션 테스트를 추가한다.
- 관리자만 장소 정보와 리뷰 삭제 요청을 처리할 수 있는지 확인한다.
- 이벤트 상세에서 연결된 장소만 상세·리뷰가 보이는지 확인한다.
- 관련 Vitest와 `pnpm exec tsc --noEmit`을 실행한다.

## 범위 밖

- 네이버 장소 데이터 자동 수집, 외부 이동·딥링크, 사진 업로드.
- 리뷰 답글, 신고, 좋아요, 정렬·검색.
- 별도 장소 상세 경로와 관리자 전용 새 대시보드 경로.
