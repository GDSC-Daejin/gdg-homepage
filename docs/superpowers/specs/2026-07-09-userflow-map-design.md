# GDG DJU 유저플로우 맵 + 갭 설계

작성일: 2026-07-09. 현행 코드(feat/mvp) 기준 실측 문서.

## 0. 진입점 구조

- 일반 회원: 좌측 사이드바 (홈/출석/공지/설문/문의/자료실/프로필)
- 관리자(`profiles.role = 'admin'`): 사이드바 하단에 **관리 > 어드민** 링크가 추가 노출됨 (`SidebarNav.tsx:73-78`)
- `/admin`은 자체 사이드바(대시보드/회원/지원서/이벤트/출석/공지/설문/문의/포인트/예산/감사 로그)를 가진 별도 레이아웃. `requireAdmin()`으로 보호.
- 최초 관리자는 DB에서 `profiles.role`을 직접 `admin`으로 변경해야 함. 이후에는 `/admin/members/[id]`에서 역할 변경 가능.

## 1. 현행 유저플로우 (이미 구현됨)

### 이벤트
- 생성: `/admin/events` 우상단 "이벤트 생성" → `/admin/events/new` (`EventForm`: 제목/유형/일시/장소/정원)
- 수정·삭제: `/admin/events` 목록 카드 클릭 → `/admin/events/[id]` (폼 + 삭제 버튼)
- 회원 열람: 홈(`/`)에서 "다가오는 이벤트" / "지난 이벤트" 분리 표시 → `/events/[id]`에서 신청(확정/대기열)

### 출석
- 코드 발급: `/admin/events/[id]` 하단 `AttendancePanel` — "코드 발급" 버튼 → 6자리 코드 + QR + 출석 링크 자동 생성
- 코드 조회: 같은 패널에 현재 코드/QR/출석 현황(출석 n / 확정 m)/신청자별 출석 여부 표시
- 회원 출석: `/attend`에서 이벤트 선택 + 코드 입력, 또는 QR 스캔 시 자동 채움
- 통계: `/admin/attendance` — 회원별 확정 신청/출석/출석률 + 경고(기준 미달) + Slack 경고 발송 버튼 + 크론 자동화
- 포인트: 출석 시 DB 트리거(`grant_attendance_points`)로 자동 적립

### 공지
- 작성: `/admin/notices` → "공지 작성" → `/admin/notices/new`
- 수정·발행·삭제: `/admin/notices/[id]` (폼 + 발행 버튼 + 삭제 버튼). 발행 시 감사 로그 기록
- 회원 열람: `/notices` — 발행된 공지만. 최신 공지는 홈 상단 배너로도 노출

### 설문
- 생성: `/admin/surveys` → "설문 생성" → `/admin/surveys/new` (질문 빌더: 텍스트/별점)
- 발행: 목록에서 열림/닫힘 토글 (`ToggleSurveyButton`) — 열림 = 회원에게 노출
- 응답 확인·요약: `/admin/surveys/[id]/results` — 별점은 평균+분포 바 차트, 텍스트는 응답 목록
- 회원 응답: `/surveys` — 열린 설문 목록(응답 완료/미응답 뱃지) → `/surveys/[id]`

### 문의
- 회원: `/inquiries` — 작성 폼 + **본인 문의 내역 + 상태(접수/답변완료) + 답변 내용** 표시
- 관리자: `/admin/inquiries` — 전체 문의 통합 목록 + `AnswerForm`으로 답변 (답변 시 상태 자동 전환)

### 포인트/뱃지
- 포인트 발행: 출석 자동 적립 + `/admin/points`의 "포인트 부여" 폼(수동, 사유/이벤트 연결)
- 뱃지 종류 관리: `/admin/points`의 "뱃지 관리" — 이모지/이름/설명으로 생성·삭제
- 뱃지 발행: `/admin/points`의 "뱃지 수여" 폼 (수동, 중복 수여 방지)
- 회원 확인: `/profile` — 누적 포인트/포인트 내역/보유 뱃지/신청·출석 이력
- 이력 추적: `/admin/points` 하단 포인트 로그 + `/admin/audit` 감사 로그

## 2. 실제 갭과 설계

### 갭 A. 기간별 이벤트 조회 없음
홈과 `/admin/events` 모두 전체 이벤트를 무한 나열. 이벤트가 쌓이면 못 씀.

**설계**: `searchParams` 기반 연-월 필터.
- 홈 "지난 이벤트" 섹션과 `/admin/events` 상단에 월 선택 드롭다운(`<select>`, 서버 컴포넌트 + 링크 방식) 추가
- 기본값: 홈은 최근 3개월, 어드민은 전체
- 쿼리는 `starts_at` 범위 필터로 서버에서 수행. 신규 테이블/시즌 개념 도입 안 함 (이벤트에 season 컬럼이 없고, 월 필터로 충분)

### 갭 B. 뱃지 카탈로그가 회원에게 안 보임
회원은 자기가 받은 뱃지만 볼 수 있어 "어떤 뱃지가 있고 어떻게 얻는지"를 알 수 없음.

**설계**: `/profile`의 "내 뱃지" 섹션을 전체 카탈로그로 변경.
- `badges` 전체 조회 + 보유 여부 매핑. 보유: 현재 스타일, 미보유: 흐리게(grayscale/opacity) + 이름/설명 노출
- `badges.description`을 획득 조건 서술란으로 사용 (예: "한 시즌 출석률 100%") — 스키마 변경 없음
- 자동 수여 조건 엔진은 만들지 않음. 수여는 지금처럼 관리자 수동 (운영 규모상 충분)

### 갭 C. 뱃지 초기 세트 미정의
`badges` 테이블이 비어 있고 종류/조건 기준이 없음.

**설계**: 코드가 아닌 운영 데이터. 아래 추천 세트를 시드(`supabase/seed.sql`)에 추가:

| 이모지 | 이름 | 획득 조건(description) |
|---|---|---|
| 🌱 | 첫 출석 | 첫 이벤트 출석 |
| 🔥 | 개근 | 한 시즌 확정 이벤트 출석률 100% |
| 🎤 | 스피커 | 세션/스터디 발표 |
| 📚 | 스터디 리더 | 스터디 1회 이상 리드 |
| 🎉 | DevFest | DevFest 참가 |
| 💡 | 아이디어 뱅크 | 채택된 건의 3회 |

### 갭 D. 플로우 문서 부재
이번 문서가 그 역할. README에 이 문서 링크 한 줄 추가.

### 갭 E. 어드민 가입/로그인 분기 없음
가입은 전부 `role='applicant'`로 생성되고, 최초 어드민은 DB 수동 변경뿐이었음.

**설계** (마이그레이션 `0006_admin_bootstrap.sql`):
- `admin_emails(email pk)` 테이블 신설. RLS 활성 + 정책 없음 → definer 함수에서만 조회 가능, 클라이언트 접근 차단
- `handle_new_user` 트리거 수정: 가입 이메일이 `admin_emails`에 있으면 `role='admin'`, 아니면 기존대로 `applicant`
- 로그인 분기: OAuth 콜백에서 `role`을 조회해 admin은 `/admin`으로, 나머지는 `/`로 리다이렉트 (온보딩 미완료 시엔 기존대로 `/onboarding` 우선)
- 운영진 이메일 등록은 seed 또는 Supabase Studio에서 직접 insert. 가입 후 승격은 기존 `/admin/members/[id]` 역할 변경 사용
- 별도 어드민 가입 페이지는 만들지 않음 — 로그인 수단은 구글 OAuth 하나로 유지, 구분은 이메일 기준

## 3. 범위에서 제외 (이유)

- 설문 예약 발행/마감일: 열림/닫힘 토글로 충분, 요청 시 추가
- 문의 카테고리/담당자 배정: 단일 관리자 운영 규모에 과함
- 뱃지 자동 수여 트리거: 조건이 사람 판단(발표, 리드 등)이라 자동화 이득 없음
- 이벤트 시즌 컬럼: 월 필터로 대체
