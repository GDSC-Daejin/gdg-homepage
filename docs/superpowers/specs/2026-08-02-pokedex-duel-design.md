# 도감 포켓몬 결투 설계

## 목표

웹 도감 안에서 활성 회원에게 1:1 결투를 신청한다. 신청자와 상대는 각각 자신이 포획한 기록 한 건을 고르고, 수락 시 서버가 전투력과 작은 난수 보정을 이용해 승패를 한 번만 확정한다. 확정된 결과는 짧은 애니메이션으로 재생한다.

## 범위

- `/pokedex`에 `결투` 탭을 추가한다.
- 활성 회원 전체를 상대 선택지로 보여 준다. 본인은 제외한다.
- 신청자와 상대 모두 전투력이 있는 성공 포획 기록 한 건을 선택한다.
- 신청자는 취소할 수 있고, 상대는 수락하거나 거절할 수 있다.
- 수락 결과는 두 포켓몬 이미지, 이름, 전투력, 공격 연출, 승패로 재생한다.

타입 상성, 기술, 턴제, 팀전, 자동 만료, Slack 알림, 전적·랭킹은 이번 버전에서 제외한다.

## 데이터와 보안

`pokemon_duels` 테이블은 신청자·상대·양측 `pokemon_throws` ID·상태(`pending`, `accepted`, `rejected`, `canceled`)·양측 전투 점수·승자·생성/해결 시각을 저장한다. 포켓몬 종이 아닌 성공 포획 기록을 참조하므로, 별도 포켓몬 인벤토리 테이블은 만들지 않는다.

RLS로 직접 쓰기를 허용하지 않는다. 세 개의 `security definer` RPC가 상태를 바꾼다.

- 신청 RPC는 호출자가 선택한 포획 기록을 소유했고 상대가 활성 회원이며 본인이 아닌지 확인한다.
- 수락 RPC는 상대만 호출할 수 있고, 선택한 포획 기록의 소유·성공 포획·전투력 존재를 확인한다. 두 전투 점수는 각각 `전투력 × 90~110%`로 계산해 저장하며, 동점은 무작위로 승자를 정한다.
- 거절과 취소 RPC는 각각 상대와 신청자만 실행할 수 있다.

모든 RPC는 대상 결투가 `pending`일 때만 변경한다. 따라서 중복 클릭이나 오래 열린 화면이 결과를 덮어쓰지 못한다.

## 화면과 애니메이션

서버 페이지는 선택 가능한 내 포획 기록, 활성 회원, 내 보낸 신청, 내 받은 신청, 최근 해결 결과를 조회한다. 작은 클라이언트 컴포넌트가 선택·신청·수락·거절·취소 상태만 담당하고 서버 액션 뒤 `/pokedex`를 갱신한다.

수락 직후 반환받은 확정 결과는 모달에서 재생한다. 양쪽 포켓몬을 마주 보게 표시한 뒤, 승자 쪽 이동·상대 흔들림·승패 문구 순서로 보여 준다. 전역 `prefers-reduced-motion` 규칙을 그대로 따라 모션을 최소화한다. 애니메이션은 결과를 표현할 뿐, 승패 계산에는 관여하지 않는다.

## 검증

- 마이그레이션 테스트는 소유권·활성 회원·`pending` 상태 검증, 점수/승자 저장, RPC 권한 회수를 확인한다.
- 도감 결투 화면 테스트는 결투 탭과 신청·수락·거절·취소 UI, 결과 재생 컴포넌트를 확인한다.
- 새 테스트는 구현 전에 실패를 확인한 뒤 최소 구현으로 통과시킨다.
- 관련 Vitest 테스트와 타입 검사를 실행한다.
