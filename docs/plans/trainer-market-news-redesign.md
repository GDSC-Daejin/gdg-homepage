# 포켓몬 주식 속보 재구성안

> 상태: Implemented

## 문제

현재 뉴스 풀은 하루의 공통 사건 문단을 다섯 종목의 본문 앞에 그대로 붙인다. 여섯 번째 종목은 별도 보강 기사다. Slack 포맷터는 여섯 본문을 순서대로 출력하므로, 같은 두 문장이 반복되고 종목별 기사의 밀도도 불균형하다.

이 때문에 사용자는 종목별 판단 근거 대신 같은 사건을 여섯 번 읽고, 각 기업의 사업 영역과 주가 움직임의 관계를 이해하기 어렵다.

## 목표

한 번의 속보에서 사용자는 아래를 10초 안에 파악한다.

1. 오늘 시장을 움직이는 사건은 무엇인가.
2. 그 사건이 어떤 순서로 여섯 기업에 번지는가.
3. 각 기업의 고유 역할과 호재·악재의 이유는 무엇인가.
4. 어느 종목을 응원할지 판단할 수 있는가.

## 콘텐츠 원칙

### 하루 한 사건, 종목별 한 역할

공통 사건은 속보 머리에서 한 번만 말한다. 종목 기사에는 사건을 반복하지 않고, 그 기업이 취한 행동과 사업상 결과만 쓴다.

| 종목 | 고정 역할 | 뉴스가 다룰 것 |
| --- | --- | --- |
| 오박사연구소 | 발견·검증·안전 기준 | 원인 규명, 관찰 결과, 운영 제한 |
| 실프 주식회사 | 신호·도구·시스템 | 연구 결과를 현장 기술로 바꾸는 대응 |
| 몬스터볼 팩토리 | 제조·보호 장비 | 생산량, 원가, 장비 수급 |
| 로켓단 홀딩스 | 운송·집하·우회 | 물류 병목, 운송 기회, 납기 위험 |
| 포켓몬센터 | 회복·안전·인력 | 사람과 포켓몬의 부담, 회복 수요 |
| 금빛시티 백화점 | 방문객·상권·소비 | 행사, 예약, 매출, 취소·환불 |

### 인과는 있으나 같은 결론은 아니다

하루에 하나의 중심 사건과 두 개 이상의 연결 고리를 둔다. 한 기업의 호재가 다른 기업의 비용·지연·수요 증가로 이어질 수 있어야 한다. 여섯 종목을 모두 호재로 만들지 않는다.

기본 흐름은 다음과 같다.

```text
원인 발견 (OAK) → 기술 대응 (SILPH)
                   ├→ 장비 수급·원가 (BALL)
                   └→ 우회 운송·병목 (ROCKET)
                              ├→ 회복·안전 수요 (CENTER)
                              └→ 방문·상권 변화 (CELADON)
```

매일 모든 화살표를 쓰지 않는다. 사건에 맞는 3~5개의 연결만 선택해 의외성은 유지하고, 모든 종목은 반드시 자기 역할의 독립된 행동을 가진다.

## Slack 메시지

이미 09:00 응원판에 종목과 매수 진입 버튼이 있으므로, 10:30 속보는 **읽는 메시지**로 분리한다. 종목별 정적 이미지 여섯 장과 매수 버튼 열두 개는 속보에서 제거한다.

```text
📰 관동 주식 속보 · 10:30

오늘의 사건
붉은 협곡 북부 통로에서 예측 불가 자기장이 감지됐어요.
탐사대는 북부 장비 반입을 멈추고 남쪽 우회로를 열기로 했어요.

연결 고리
안전선 확정 (OAK) → 우회 신호 (SILPH) → 남쪽 물류 집중 (ROCKET)
                                      └→ 보호 장비 긴급 전환 (BALL)

🔬 오박사연구소 · 강한 호재 📈
*자기장 경계선 세 곳 확정*
현장팀이 통행 가능 구간을 확정해 탐사 재개 기준을 제시했어요.

🧪 실프 주식회사 · 관망 ⚪
*우회 신호 장치 현장 시험*
안전선 안에서만 작동하는 임시 신호를 설치했지만, 시험 결과를 더 지켜봐야 해요.

🏭 몬스터볼 팩토리 · 악재 📉
*북부용 보호 상자 재포장*
이미 출고한 물량을 우회 운송 규격으로 다시 묶으며 추가 작업이 생겼어요.

🚀 로켓단 홀딩스 · 호재 📈
*남쪽 집하장 야간 증편*
우회 물량이 몰리자 비어 있던 야간 노선을 투입해 운송 계약을 늘렸어요.

❤️ 포켓몬센터 · 관망 ⚪
*대기 인원 회복 부스 확대*
우회 대기 시간이 길어진 트레이너와 포켓몬을 위해 임시 회복 부스를 열었어요.

🏬 금빛시티 백화점 · 악재 📉
*협곡 체험 예약 일괄 연기*
북부 통로 일정이 불확실해지면서 주말 체험 상품의 날짜 변경을 받기 시작했어요.
```

원칙은 다음과 같다.

- 공통 사건은 2문장 이내, 속보 전체는 모바일에서 한 화면 반 이내로 유지한다.
- 종목별 기사는 `제목 1줄 + 결과 1문장`만 쓴다.
- 종목별 본문에 공통 사건의 문장 또는 첫 구절을 재사용하지 않는다.
- 호재·악재 표시는 결과 요약이지, 기사 제목을 대체하지 않는다.
- 매수는 09:00 응원판의 종목 버튼에서만 시작한다. 속보는 매수 버튼을 반복하지 않는다.

## 데이터와 생성 방식

### 확정 운영: 검수된 30일 에피소드 묶음

이번 범위는 AI 생성 없이, 검수된 30일치 **에피소드 묶음**만 사용한다. 하루 묶음은 `오늘의 사건`, `연결 고리`, `장마감 결말`, 여섯 종목 기사로 구성한다. 현재처럼 각 기사 본문에 공통 사건을 저장하지 않는다.

30일 서사는 현재의 붉은 협곡 전력망·개통 이야기로 유지한다. 단, 하루 안에서는 각 종목의 고정 역할과 인과가 분명하도록 전면 재작성한다. 30일 이후의 새 서사는 별도 기획으로 추가한다.

### 저장 모델

| 테이블 | 필드 | 용도 |
| --- | --- | --- |
| `trainer_market_story_pool` | `market_date`, `title`, `summary`, `causal_chain`, `closing_note` | 검수된 30일 에피소드 원본 |
| `trainer_market_news_pool` | 기존 `market_date`, `symbol`, `headline`, `body`, `sentiment`에 `angle`, `predecessors` 추가 | 에피소드 안의 여섯 종목 기사 원본 |
| `trainer_markets` | `story_title`, `story_summary`, `story_causal_chain`, `story_closing_note` 추가 | 당일 게시·장마감에 쓰는 에피소드 스냅샷 |
| `trainer_market_news` | 기존 여섯 종목 기사 스냅샷을 유지 | 종가 계산에 쓰는 감성 및 게시 이력 |

`angle`은 `research`, `technology`, `manufacturing`, `logistics`, `care`, `retail` 중 하나로, 각각 `OAK`, `SILPH`, `BALL`, `ROCKET`, `CENTER`, `CELADON`에 고정한다. `predecessors`는 해당 기사가 어떤 선행 종목 또는 중심 사건의 결과인지 표현하는 종목 코드 배열이다. 화면에는 `causal_chain`만 보여 주고, 두 필드는 콘텐츠 검증에 쓴다.

09:00 시장 개장 시 풀의 에피소드 한 건과 여섯 기사를 당일 테이블로 복사한다. 같은 날짜의 시장이 이미 있으면 다시 복사하지 않는다. 풀의 과거 데이터를 수정해도 이미 게시한 당일 속보와 장마감 기록은 바뀌지 않는다.

## 확정 UX와 메시지 책임

| 시각 | 메시지 | 포함 | 제외 |
| --- | --- | --- | --- |
| 09:00 | 응원판 | 종목명, 현재가, 매수 진입 버튼 | 사건 상세, 종목별 기사 |
| 10:30 | 관동 주식 속보 | 사건·인과·여섯 종목 기사 | 이미지, 매수 버튼 |
| 22:00 | 장마감 | 에피소드 결말 한 줄, 가격 결과, 수익·손실 | 오전 사건의 반복 설명 |

10:30 메시지의 기사 순서는 인과를 읽기 쉬운 `OAK → SILPH → BALL → ROCKET → CENTER → CELADON`으로 고정한다. 당일 실제 인과가 다르더라도 이 순서를 유지해 사용자가 매일 같은 위치에서 같은 기업을 찾게 한다.

속보는 Slack `section` 블록 하나로 보낸다. 이미지와 12개의 버튼은 보내지 않는다. 종목을 매수하려는 사용자는 09:00 응원판으로 돌아간다.

## 콘텐츠 제약과 자동 검증

각 에피소드 묶음은 저장 전 다음을 충족해야 한다.

| 항목 | 규칙 |
| --- | --- |
| 사건 | 제목 4~60자, 요약 2문장·30~220자, 동일한 문장을 종목 기사에 쓰지 않음 |
| 인과 | `causal_chain`에 종목 코드 세 개 이상, 각 종목 기사는 `predecessors`에 사건 또는 다른 종목 한 개 이상 |
| 종목 수 | 여섯 종목을 정확히 한 번씩 포함 |
| 역할 | `angle`이 종목별 고정 역할과 일치하고, 기사는 해당 역할을 다룸 |
| 중복 | 정규화한 제목·본문·첫 문장이 한 묶음 안에서 모두 고유 |
| 감성 | `-2`~`2`의 종목별 결과가 기사 내용과 맞고, 여섯 종목이 모두 같은 감성이 아님 |
| 문체 | 현실 기업·투자 조언·현실 가격·멘션·링크·줄바꿈을 쓰지 않음 |

자동 검증은 풀 데이터와 당일 복사 결과 모두에 적용한다. 오류가 있으면 10:30 속보를 보내지 않고 크론을 실패 처리한다.

## 구현 범위

1. 일일 에피소드·기사 선행 관계·당일 스냅샷 필드를 추가하는 마이그레이션을 만든다.
2. 기존 30일 뉴스 풀을 새 에피소드 묶음으로 다시 쓴다. 협곡 서사는 유지하되, 하루마다 여섯 역할·세 개 이상 인과·혼합 감성을 만족시킨다.
3. 풀과 당일 스냅샷을 검증하는 순수 함수를 만들고, 중복·역할·인과·종목 누락 테스트를 작성한다.
4. 시장 개장 경로가 에피소드 묶음을 원자적으로 복사하게 바꾼다.
5. 10:30 Slack 속보를 확정 포맷으로 교체하고 이미지·매수 버튼을 제거한다.
6. 22:00 장마감에 `story_closing_note` 한 줄을 추가한다. 09:00 응원판은 가격과 종목 선택만 담당하게 둔다.

## 완료 기준

- 같은 문장이 한 속보 안에 두 번 나타나지 않는다.
- 여섯 기사가 모두 각 종목의 고정 역할에 맞는다.
- 각 속보에는 최소 세 개의 명시적 인과 연결이 있다.
- 09:00 응원판과 10:30 속보의 역할이 겹치지 않는다.
- 고정 뉴스 풀 30일과 당일 스냅샷 모두 위 규칙을 자동 검증한다.

## 이번 결정에서 제외한 것

- AI 뉴스 생성 및 재생성
- 속보 메시지의 종목별 이미지
- 속보 메시지의 직접 매수 버튼
- 30일 이후 서사와 운영자 편집 화면
