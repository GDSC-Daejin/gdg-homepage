# 신규 멤버 모집 프로세스 기획·설계

> 이 문서는 신규 멤버 모집의 최신 기준 문서다. 면접 운영 여부와 세부 운영 규칙은 이 문서를 기준으로 하며, 기존 IA 기획서의 면접 미운영 내용은 대체된 것으로 본다.

## 1. 목표

공개 지원부터 멤버 승인까지의 모집 과정을 하나의 운영 흐름으로 연결한다.

- 지원서와 면접 일정을 분리해 관리한다.
- 면접 취소·변경·노쇼 이력을 보존한다.
- 서류·면접 평가를 구조화한다.
- 최종 합격자를 초대 링크로 가입시키고 지원서와 계정을 연결한다.
- 운영진이 합격자의 가입·승인 진행 상태를 확인할 수 있게 한다.

## 2. 확정 결정

- 면접 취소·변경 마감은 면접 시작 24시간 전이다.
- 지원자는 일정 변경을 1회만 할 수 있다.
- 운영진의 취소·변경은 제한하지 않는다.
- 노쇼 시 지원서 상태와 면접 이력을 모두 기록한다.
- 노쇼·변경·취소 이력은 운영진 화면에서만 조회한다.
- 노쇼는 기본적으로 모집 프로세스를 종료한다.
- 운영진이 예외적으로 재면접을 열 수 있다.
- 합격자 가입 후 운영진 승인을 유지한다.
- 합격자 가입은 초대 링크로 처리한다.
- 가입 초대 유효기간은 7일이다.
- 면접 평가는 1~5점 항목과 종합 의견을 사용한다.

## 3. 전체 흐름

```text
모집 설정
  → 공개 지원
  → 서류 검토
  → 면접 대상자 확정
  → 면접 초대
  → 일정 예약
  → 면접 진행
  → 참석·노쇼 기록
  → 서류·면접 평가
  → 최종 합격·불합격
  → 합격자 가입 초대
  → 계정 연결·온보딩
  → 운영진 승인
```

## 4. 상태 모델

지원서, 면접, 가입 상태를 별도로 관리한다.

### 4.1 지원서 상태

- `waiting`: 지원서 접수
- `reviewing`: 서류 검토 중
- `pending`: 면접 단계 (`interview`는 업무상 표현이며 DB 상태값은 `pending`)
- `accepted`: 최종 합격
- `rejected`: 불합격
- `no_show`: 면접 노쇼로 종료
- `withdrawn`: 지원 철회

`no_show`가 `pending`으로 되돌아가는 예외 재면접이 발생하면 상태 이력에 노쇼를 남기고 현재 상태만 `pending`으로 변경한다.

정상 전이는 다음과 같다.

```text
waiting → reviewing → pending → accepted
                                  └────→ rejected
                                  └────→ no_show
```

운영진의 예외 재면접만 `no_show → interview`를 허용한다.

### 4.2 면접 상태

- `invited`: 초대 발송
- `booked`: 일정 예약
- `canceled`: 취소
- `completed`: 면접 완료
- `no_show`: 노쇼

변경은 별도 현재 상태가 아니라 예약 이력으로 관리한다.

### 4.3 가입 상태

- `not_invited`: 가입 초대 전
- `invited`: 가입 초대 발송
- `account_linked`: 지원서와 계정 연결
- `profile_pending`: 프로필 작성 중
- `approval_pending`: 운영진 승인 대기
- `approved`: 멤버 승인
- `expired`: 초대 만료

가입 상태는 초대 사용 여부, 지원서-프로필 연결 여부, 프로필 승인 여부를 조합해 운영진 화면에 표시한다.

## 5. 지원자 흐름

### 공개 지원

지원자는 로그인 없이 `/apply`에서 지원한다.

필수 정보:

- 이름
- 학번
- 전공
- 전화번호
- 이메일
- 지원 포지션
- 자기소개
- 지원 동기
- 관심 분야

지원 완료 후에는 접수 완료 메시지만 표시한다. 지원 상태는 결과 이메일로 안내한다.

### 면접 예약

1. 운영진이 `pending` 상태(면접 단계) 지원자에게 초대 이메일을 보낸다.
2. 지원자는 이메일의 토큰 링크로 접속한다.
3. 미래의 빈 슬롯 중 하나를 선택한다.
4. 예약이 확정되면 Google Meet과 Calendar를 생성한다.
5. 지원자와 면접관에게 확정 이메일을 보낸다.

### 취소·변경

- 면접 24시간 전까지 취소 가능
- 면접 24시간 전까지 일정 변경 가능
- 지원자 변경 횟수는 1회
- 취소 후 남은 변경 횟수로 다시 예약할 수 있다.
- 운영진 변경·취소는 별도 제한 없이 처리한다.
- 외부 Calendar 삭제·생성 실패는 내부 예약을 되돌리지 않고 운영진에게 재동기화를 요구한다.

### 노쇼

운영진이 면접 시작 이후 참석 또는 노쇼를 기록한다.

- 참석: 면접 완료로 기록하고 최종 평가 단계로 이동
- 노쇼: 면접 이력에 기록하고 지원서 상태를 `no_show`로 변경
- 노쇼 사유와 처리자·처리 시각을 저장
- 기본적으로 추가 예약은 막음
- 예외 재면접 시 노쇼 이력을 보존하고 새 면접을 생성

## 6. 운영진 흐름

### 지원서 관리

- 시즌별 지원서 목록
- 포지션·상태·이름·학번 검색
- 지원서 답변 확인
- 서류 평가 작성
- 면접 대상자 전환
- 최종 합격·불합격 처리
- 상태 변경 이력 확인

### 면접 관리

- 면접 슬롯 생성
- 면접관 배정
- 초대 이메일 발송
- 예약·변경·취소 확인
- Google Meet 링크 확인
- Calendar 동기화 상태 확인
- 참석·노쇼 처리
- 노쇼 예외 재면접

### 합격자 전환 관리

- 가입 초대 전
- 초대 발송
- 가입 미완료
- 계정 연결 완료
- 승인 대기
- 승인 완료
- 초대 재발송

## 7. 평가 설계

평가자는 서류 평가와 면접 평가를 각각 제출한다.

초기 평가 항목:

- 지원 동기
- 커뮤니케이션
- 협업 가능성
- 직무·포지션 적합성
- 활동 가능성
- 성장 가능성

각 항목은 1~5점으로 기록하고 종합 의견을 작성한다.

- 평가자는 여러 명일 수 있다.
- 제출 전에는 다른 평가자의 평가를 보지 않는다.
- 제출 후에는 수정 이력을 남긴다.
- 평가 결과가 최종 합격을 자동 결정하지 않는다.
- 최종 결정은 운영진이 별도로 수행한다.

## 8. 합격자 가입 연결

1. 운영진이 지원서를 `accepted`로 변경한다.
2. 시스템이 7일 유효한 가입 초대 토큰을 생성한다.
3. 합격자 이메일로 가입 링크를 발송한다.
4. 합격자가 Google 로그인한다.
5. 초대 토큰과 로그인 계정을 검증한다.
6. `applications.applicant_id`에 계정의 프로필 ID를 연결한다.
7. 지원서 정보를 온보딩 기본값으로 제공한다.
8. 합격자는 프로필을 작성한다.
9. 운영진이 승인하면 멤버 기능을 사용할 수 있다.

이메일 주소만으로 자동 연결하지 않는다. 초대 토큰과 대상 이메일을 함께 검증한다.

초대 링크는 원문 토큰을 DB에 저장하지 않고 해시값을 저장한다. 사용 시각, 만료 시각, 연결 계정을 함께 기록한다.

## 9. 데이터 설계

### 기존 테이블 유지·확장

#### `applications`

- 현재 지원서 정보와 현재 지원서 상태 저장
- `applicant_id`로 최종 가입 계정 연결
- `reviewed_by`, `reviewed_at`, `review_note` 유지
- `no_show` 상태 유지

#### `interview_slots`

- 면접 일정·면접관·Meet·Calendar 정보 저장
- 참석 결과 저장

#### `interview_booking_events`

- 예약
- 지원자 변경·취소
- 운영진 변경·취소
- 참석
- 노쇼

### 추가 테이블

#### `application_status_history`

- `application_id`
- `from_status`
- `to_status`
- `actor_type`
- `actor_id`
- `reason`
- `created_at`

지원서 상태 변경 이력을 보존해 노쇼 후 재면접 같은 예외 처리를 추적한다.

#### `application_evaluations`

- `application_id`
- `evaluator_id`
- `stage`: `document` 또는 `interview`
- 항목별 점수
- `recommendation`: 합격·보류·불합격
- `note`
- `submitted_at`
- `updated_at`

#### `application_onboarding_invites`

- `application_id`
- 토큰 해시
- 대상 이메일
- `expires_at`
- `used_at`
- 연결된 프로필 ID
- 생성자
- 생성 시각

## 10. 권한

지원자는 다음만 수행할 수 있다.

- 공개 지원서 제출
- 본인 초대 토큰으로 면접 예약·취소·변경
- 본인 합격 초대 토큰으로 가입·계정 연결

운영진만 수행할 수 있다.

- 지원서 조회·상태 변경
- 평가 작성·조회
- 면접 슬롯 생성·변경·취소
- 참석·노쇼 기록
- 가입 초대 재발송
- 멤버 승인
- 이력 조회

지원자는 다른 지원자의 정보나 면접 이력을 조회할 수 없다.

## 11. 외부 연동 실패 처리

- 지원서·면접·평가·가입 연결을 Supabase의 내부 데이터로 먼저 저장한다.
- Resend 실패는 발송 실패로 표시하고 재발송할 수 있게 한다.
- Google Meet 생성 실패는 예약을 유지하고 운영진이 재생성한다.
- Google Calendar 실패는 예약을 유지하고 재동기화한다.
- 외부 연동 실패가 최종 합격·노쇼 같은 내부 상태 변경을 취소하지 않도록 한다.

## 12. 범위 제외

초기 구현에서는 다음을 포함하지 않는다.

- 지원자용 지원 상태 조회 페이지
- 자동 점수 기반 합격 결정
- 면접 자동 녹화·전사
- 자동 참석 감지
- 자동 노쇼 판정
- 지원자와 운영진의 실시간 채팅
- 지원서 제출 후 답변 수정

## 13. 완료 조건

- 지원서·면접·가입 상태가 운영진 화면에서 구분되어 보인다.
- 서류·면접 평가를 평가자별로 저장할 수 있다.
- 최종 합격 처리 시 가입 초대가 발송된다.
- 초대 링크를 사용한 계정만 지원서와 연결된다.
- 합격자의 가입·프로필·승인 진행 상태를 확인할 수 있다.
- 면접 24시간 전 제한과 지원자 변경 1회 제한이 동작한다.
- 취소·변경·참석·노쇼 이력이 보존된다.
- 노쇼 지원서는 운영진 화면에서 확인할 수 있다.
- 운영진 예외 재면접 시 기존 노쇼 이력이 사라지지 않는다.
- 이메일·Meet·Calendar 실패 시 내부 데이터가 유실되지 않는다.
- 기존 공개 지원과 멤버 승인 흐름이 회귀하지 않는다.

## 14. 구현 순서

1. 상태 및 상태 이력 정리
2. 구조화 평가 저장·운영진 화면 추가
3. 합격자 가입 초대와 지원서-프로필 연결
4. 합격자 전환 현황 화면 추가
5. 결과 이메일·가입 초대 재발송 처리
6. 기존 면접 취소·변경·노쇼 흐름과 통합
7. 문서·테스트 정리

## 15. 화면 기획

### 15.1 지원자 지원 화면 `/apply`

- 모집 상태와 현재 시즌을 상단에 표시한다.
- 지원 절차를 `서류 접수 → 서류 심사 → 면접 진행 → 결과 이메일` 순서로 보여준다.
- 모집 마감 시 지원 폼 대신 마감 안내와 활동 페이지 이동을 제공한다.
- 입력 오류와 제출 중 상태를 폼 안에서 바로 안내한다.

### 15.2 지원자 면접 화면 `/interview`

- 토큰이 유효하지 않거나 예약 가능한 시간이 없을 때 별도 안내를 보여준다.
- 예약 전에는 선택 가능한 슬롯과 예약 버튼을 보여준다.
- 예약 후에는 면접 일시, Meet 링크, 취소·변경 가능 여부를 보여준다.
- 면접 시작 24시간 전 마감 정책과 일정 변경 가능 횟수를 행동 영역 근처에 안내한다.

### 15.3 운영진 지원서 상세 `/admin/applications/[id]`

- 현재 지원서 상태와 다음 처리 행동을 상단에서 확인한다.
- 지원 답변, 구조화 평가, 면접 이력, 상태 이력을 순서대로 배치한다.
- 최종 결정 후 결과 이메일 재발송을 제공한다.
- 취소 이력에는 취소 메일 재발송을 제공하고, 노쇼 이력에는 사유를 표시한다.

### 15.4 운영진 면접 관리 `/admin/interviews`

- 슬롯·예약·완료·노쇼 건수를 상단 요약 카드로 제공한다.
- 슬롯 생성과 면접 초대 발송을 예약 현황보다 위에 배치한다.
- 예약 현황에서 Meet, Calendar, 확정 메일, 취소·변경, 참석·노쇼를 관리한다.

### 15.5 합격자 전환 `/admin/applications/conversions`

- 합격자별 전환 상태를 `초대 전 → 초대 발송 → 계정 연결 → 승인 대기 → 승인 완료`로 표시한다.
- 초대 만료일과 재발송 행동을 같은 행에서 제공한다.
