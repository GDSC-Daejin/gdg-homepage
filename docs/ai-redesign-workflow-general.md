# AI 리디자인 워크플로 (범용)

화면을 새로 만들기 전에 **레퍼런스 이미지로 방향을 먼저 합의하고**, 선택한 규칙만 기존 화면에 적용한다. 디자인 작업 중 기능, API, 정보 구조를 임의로 바꾸지 않는다.

## 1. 입력 정리

작업 시작 전 아래 네 가지만 정한다.

- 현재 화면의 데스크톱 스크린샷 (모바일 화면이 있으면 함께)
- 유지할 것 3개: 예) 브랜드 색감, 현재 탭 구성, 주요 작업 흐름
- 바꿀 것 3개: 예) 정보 위계, 표 가독성, 패널 간 구분
- 범위: 화면 하나인지, 여러 화면에 적용할 공통 규칙인지

프로젝트의 디자인 시스템, 컴포넌트 규칙, 접근성 기준이 있으면 먼저 확인한다.

## 2. 현재 화면 해부

코드를 바꾸기 전에 화면을 아래 다섯 영역으로 나눈다.

| 영역 | 확인할 것 |
| --- | --- |
| 전역 영역 | 헤더, 사용자 역할, 전역 내비게이션 |
| 페이지 이동 | 탭, 필터, 검색, 정렬 |
| 핵심 작업 | 사용자가 가장 자주 읽거나 조작하는 정보 |
| 보조 정보 | 상태, 도움말, 메타데이터 |
| 데이터 계약 | API 호출, URL, 분석 이벤트, 테스트 셀렉터 |

이 단계의 결과는 “무엇을 옮기거나 합칠지”와 “건드리면 안 되는 동작”의 목록이다.

## 3. 레퍼런스 이미지 생성

이미지는 구현물이 아니라 **디자인 합의용 시안**이다. 외부 서비스 화면을 복사하지 않고, 현재 화면과 요구사항을 입력으로 사용한다.

프롬프트 템플릿:

```text
첨부한 [현재 화면]을 바탕으로 [제품/사용자 역할]의 [데스크톱 또는 모바일] 화면을 리디자인한다.
유지: [브랜드·색감·정보 구조·핵심 흐름].
개선: [정보 위계·탐색 구조·콘텐츠 배치].
중요 작업은 [핵심 작업]이며 한눈에 읽혀야 한다.
스타일: [기존 브랜드와 어울리는 시각 규칙].
실제 브랜드·개인 정보는 넣지 말고, 구현 가능한 웹 UI 레퍼런스로 만든다.
```

한 번에 한 안만 생성하고, 마음에 들지 않을 때만 수정 조건을 하나씩 바꿔 재생성한다.

## 4. 시안에서 규칙만 추출

선택한 이미지에서 아래 항목만 문장으로 고정한다. 이미지를 픽셀 단위로 복제하지 않는다.

- 위계: 전역 메뉴, 페이지 이동, 핵심 작업의 우선순위
- 표면: 캔버스, 카드·패널, 구분선의 역할
- 강조: 브랜드색과 경고색을 쓰는 상태
- 밀도: 여백, 행 높이, 제목과 보조문구의 크기 차이
- 반응형: 좁은 화면에서 숨길 정보와 세로로 쌓을 영역

추출한 규칙은 기존 토큰과 컴포넌트로 표현한다. 새 색, 폰트, 라이브러리는 꼭 필요할 때만 추가한다.

## 5. 최소 구현

기능별로 한 번에 한 덩어리만 바꾼다.

1. 기존 컴포넌트와 호출처를 찾고, 재사용 가능한 패널, 탭, 테이블 패턴을 고른다.
2. 데이터 흐름과 접근성 속성, 테스트 셀렉터는 유지한 채 배치와 스타일만 바꾼다.
3. 같은 정보를 두 곳에 복제하지 않는다.
4. 새 디자인이 기능 변경을 요구하면, 디자인 작업과 기능 작업을 별도 범위로 분리한다.

큰 리디자인은 기존 화면을 바로 교체하지 말고, 별도 미리보기 경로 또는 브랜치에서 검토한다.

## 6. 검증과 다음 반복

- 변경 파일의 타입 검사와 가장 작은 관련 테스트를 실행한다.
- 링크, 키보드 조작, 빈 상태, 오류 상태, 테스트 셀렉터가 남았는지 diff로 확인한다.
- 완성된 화면을 기준 스크린샷과 비교해 “정한 규칙을 지켰는지”만 검토한다.
- 수정 요청이 오면 이미지 전체를 다시 만들지 않고, 해당 규칙 하나를 바꾼 뒤 같은 컴포넌트에 적용한다.

## 완료 기준

- 선택한 레퍼런스에서 추출한 규칙이 짧은 목록으로 남아 있다.
- 변경 범위 밖의 기능, API, 정보 구조는 바뀌지 않았다.
- 기존 디자인 시스템과 접근성, 테스트 규칙을 지켰다.
- 타입 검사와 관련 테스트가 통과했다.
