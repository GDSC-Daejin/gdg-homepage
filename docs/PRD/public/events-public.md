# Events (공개)

## 페이지 기본 정보

| 항목 | 내용 |
|---|---|
| 라우트 | /events |
| 접근 권한 | 비로그인 (공개) |
| 한 줄 목적 | 다가오는 모임·행사 일정을 시간순으로 보여준다 |
| 대상 사용자 | 참여를 고민 중인 예비 회원, 일정이 궁금한 외부 방문자 |

로그인 페이지의 "NEXT MEETUP" 배지와 같은 데이터 성격(날짜·제목·설명)을 리스트 형태로 확장한 페이지다. 회원 전용 대시보드의 이벤트 목록(`/(member)`)과는 별개로, 로그인 없이 볼 수 있는 공개 일정표 역할.

## 정보 구조

1. **뒤로가기 네비** — "← 로그인으로 돌아가기"
2. **Hero / 타이틀** — "EVENTS" + 한 줄 설명 ("다가오는 모임과 행사 일정입니다")
3. **행사 리스트** — 날짜순 4건, 구분선으로 분리

## 주요 UI 요소 · 표시 데이터

각 행사 항목이 보여주는 필드:
- 날짜 (예: `2026.03.14`) — 강조 색상(Google Yellow)으로 표시
- 제목 (예: "DevFest Warm-up")
- 설명 (일시·장소·트랙 정보를 한 줄로, 예: "매주 목요일 저녁, 세미나실 B · 웹·AI·클라우드 스터디")

현재 등록된 4건: DevFest Warm-up(정기 스터디), Android 핸즈온, 교내 해커톤(48시간), DevFest DJU(연례 컨퍼런스).

## 상태 (States)

- 정적 목록, 현재 빈 상태/페이지네이션 없음. 행사가 없을 경우의 빈 상태는 향후 고려 필요.

## 인터랙션 · 액션

- 읽기 전용 목록. 항목 클릭 시 상세 이동 등의 동작은 현재 없음 (추후 상세 페이지 연결 여지 있음).

## 디자인 의도 · 강조점

- 날짜가 스캔의 1순위 키 — 타임라인/캘린더 느낌의 강한 좌측 정렬 유지.
- 정기 모임(매주)과 단발 이벤트(해커톤, 컨퍼런스)가 섞여 있으므로, 재설계 시 "정기 스터디" vs "특별 이벤트" 같은 유형 구분(배지/아이콘)을 추가하면 정보 스캔이 쉬워짐.
- 로그인 페이지의 Google 4색 팔레트를 이벤트 유형별 색상 코딩에 활용 가능.

## 반응형 · 접근성 노트

- 단일 컬럼 리스트, `max-w-2xl` — 모바일에서도 동일 레이아웃으로 문제 없음.
- 날짜 강조색이 유일한 시각적 구분 수단이므로, 색만으로 구분하지 않도록 굵기/크기 차등도 함께 유지.
