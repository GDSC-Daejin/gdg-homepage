# Projects

## 페이지 기본 정보

| 항목 | 내용 |
|---|---|
| 라우트 | /projects |
| 접근 권한 | 비로그인 (공개) |
| 한 줄 목적 | 멤버들이 진행 중인 프로젝트를 카드로 보여준다 |
| 대상 사용자 | 커뮤니티의 실제 산출물이 궁금한 예비 회원, 채용/협업을 검토하는 외부 방문자 |

로그인 페이지의 "FEATURED PROJECTS" 미니 리스트(3건)를 전체 목록(4건)으로 확장한 쇼케이스 페이지.

## 정보 구조

1. **뒤로가기 네비** — "← 로그인으로 돌아가기"
2. **Hero / 타이틀** — "PROJECTS" + 한 줄 설명 ("멤버들이 진행 중인 프로젝트입니다")
3. **프로젝트 카드 그리드** — 2열(모바일 1열) 카드 4개

## 주요 UI 요소 · 표시 데이터

카드당 필드:
- 색상 점(dot) — 프로젝트별 고유 색상 (Google 4색 순환: Blue/Red/Yellow/Green)
- 프로젝트명 (예: "Campus Map AI")
- 설명 — 한 줄로 "무엇인지 · 사용 기술" (예: "캠퍼스 길찾기 · Gemini 기반")

현재 등록된 4건: Campus Map AI(Gemini), DevFest Hub(Firebase), StudyMate(Flutter), GDG Bot(Cloud Functions).

## 상태 (States)

- 정적 카드 그리드. 빈 상태/로딩 없음.

## 인터랙션 · 액션

- 읽기 전용. 카드 클릭 시 상세/저장소 링크 이동 등은 현재 미구현 — 재설계 시 프로젝트 상세(설명, 참여자, 링크)로 연결하는 액션을 고려할 만함.

## 디자인 의도 · 강조점

- 각 카드는 "색상 점 = 프로젝트 아이덴티티" 규칙을 이미 갖고 있음 — 로고나 스크린샷이 없는 대신 색으로 구분하는 미니멀한 톤. 재설계 시 실제 썸네일/스크린샷을 추가할지, 이 미니멀 톤을 유지할지 결정 포인트.
- 사용 기술 스택(Gemini, Firebase, Flutter, Cloud Functions)이 구글 생태계 활용을 보여주는 핵심 신호 — 배지 형태로 더 강조 가능.
- 카드 그리드는 2열이 기본값 — 프로젝트 수가 늘어날 경우의 스크롤/필터 여지 고려.

## 반응형 · 접근성 노트

- `sm:grid-cols-2` — 모바일 1열, 태블릿 이상 2열. 데스크톱에서 3~4열 확장 여지 있음.
- 색상 점만으로 프로젝트를 구분하지 않도록 텍스트 레이블이 항상 함께 표시됨(현재도 그렇게 되어 있음, 유지 권장).
