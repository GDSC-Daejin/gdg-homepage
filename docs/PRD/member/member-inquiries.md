# 문의/건의 (회원)

## 페이지 기본 정보

| 항목 | 내용 |
|---|---|
| 라우트 | /inquiries |
| 접근 권한 | 회원 (`requireProfile`) |
| 한 줄 목적 | 궁금한 점이나 건의사항을 남기고, 남긴 문의와 어드민 답변을 확인한다 |
| 대상 사용자 | 문의를 등록하거나 이전에 등록한 문의의 답변을 확인하려는 회원 |

## 페이지 목적 · 사용자 목표

- 새 문의(제목+내용)를 작성해 제출한다.
- 본인이 등록한 문의 내역과 각 문의의 처리 상태(접수/답변완료)를 확인한다.
- 답변완료된 문의는 어드민 답변 내용을 확인한다.

## 정보 구조 (Information Architecture)

1. **페이지 헤더** — "문의/건의" + 설명 문구
2. **문의 작성 폼 카드** — 제목/내용 입력 + 제출 버튼 (페이지 상단 고정 위치)
3. **내 문의 내역 리스트** — 최신순(`created_at` desc), 카드 단위로 나열. 비어있으면 빈 상태 안내

## 주요 UI 요소 · 표시 데이터

- **작성 폼**: 제목(`title`, 필수), 내용(`body`, textarea 5행), 제출 버튼
- **문의 카드** (건별):
  - 제목(`title`), 등록일시(`created_at`, KST)
  - 상태 배지: `pending`(접수, warning) / `answered`(답변완료, success)
  - 문의 본문(`body`, 줄바꿈 유지)
  - 답변완료 시에만: 회색 배경 서브 블록에 "답변" 라벨 + 답변 내용(`answer`) + 답변일시(`answered_at`)
- **빈 상태**: "문의 내역이 없어요" + "위 폼으로 문의를 남겨보세요"

## 상태 (States)

- 문의 목록 없음 → EmptyState
- 제출 처리 중 → 제출 버튼 disabled
- 제출 실패 → 폼 하단 인라인 에러 텍스트
- 제출 성공 → 폼 초기화(reset), 목록에 새 문의 반영(재조회 시)
- 미답변 문의는 답변 섹션 자체가 렌더링되지 않음(접힘이 아니라 미노출)

## 인터랙션 · 액션

- 폼 제출 → 서버 액션(`submitInquiry`) 호출 → 성공 시 폼 리셋, 실패 시 에러 메시지 표시
- 문의 카드는 읽기 전용 — 수정/삭제 기능 없음
- 별도 필터/검색 없음(전체 내 문의를 최신순으로만 나열)

## 디자인 의도 · 강조점

- 작성 폼이 페이지 최상단에 위치 — "새 문의를 남긴다"가 1차 목적임을 강조.
- 상태 배지(접수 vs 답변완료)는 한눈에 구분되는 색 대비 필요 — 미답변 문의가 남아있음을 인지시키는 역할.
- 답변 블록은 문의 본문과 시각적으로 구분(배경색 차등)해 "누가 남긴 말인지" 명확히.

## 반응형 · 접근성 노트

- textarea에 label이 연결되어 있음(`useId` 기반) — 디자인 변경 시에도 label-input 연결 유지 필요.
- 상태는 배지 텍스트로 항상 함께 표기되어 색맹 사용자도 구분 가능.
- 모바일에서 문의 카드 내 상태 배지가 제목과 겹치지 않도록 줄바꿈/배치 고려.
