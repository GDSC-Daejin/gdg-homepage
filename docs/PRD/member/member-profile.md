# 내 프로필

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /profile |
| 접근 권한 | 회원 (로그인 + 프로필 등록 완료) |
| 한 줄 목적 | 내 정보를 수정하고, 활동 이력·포인트·뱃지를 한 화면에서 확인한다 |
| 대상 사용자 | 모든 회원 |

## 페이지 목적 · 사용자 목표
- 개인 정보(이름/학번/전공/전화번호/관심분야)를 수정한다
- 이벤트 신청·출석 이력을 확인한다
- 누적 포인트와 최근 적립/차감 내역을 확인한다
- 획득한 뱃지와 아직 획득하지 못한 뱃지를 한눈에 비교한다

## 정보 구조 (Information Architecture)
중앙 정렬 단일 컬럼(최대 폭 제한), 위→아래 4개 섹션
1. 내 프로필 폼 (헤더 포함)
2. 신청/출석 이력 리스트
3. 내 포인트 — 요약 통계 + 최근 내역 리스트(최대 10건)
4. 뱃지 — 보유/미보유 카드 그리드

## 주요 UI 요소 · 표시 데이터
- 프로필 폼: 이름(필수), 학번, 전공, 전화번호, 관심 분야 체크박스(기존 값 반영)
- 이력 카드: 이벤트 제목(삭제된 경우 "삭제된 이벤트"), 일시, 신청 상태 뱃지(확정=success/대기=warning), 출석 여부 뱃지("출석완료", 해당 시에만)
- 포인트 요약: StatCard "누적 포인트" (모든 point_logs amount 합산)
- 포인트 내역 카드: 사유(reason), 발생 일시, 증감액(양수는 초록 "+N", 음수는 빨강 그대로 표시)
- 뱃지 카드: 아이콘(emoji), 이름, 설명, 보유 시 "획득" 텍스트 강조 / 미보유 시 카드 전체 회색조+반투명 처리

## 상태 (States)
- 신청 이력 없음: "신청 내역이 없어요" 빈 상태
- 포인트 내역 없음: "포인트 내역이 없어요" 빈 상태 (단, 누적 포인트 StatCard는 항상 표시, 0으로)
- 등록된 뱃지 카탈로그 자체가 없음: "등록된 뱃지가 없어요" 빈 상태
- 프로필 저장 중: 버튼 비활성화
- 저장 성공: "저장됐어요" 초록 텍스트
- 저장 실패: 에러 텍스트

## 인터랙션 · 액션
- 프로필 폼 저장 → 성공/실패 인라인 피드백, 페이지 이동 없음
- 나머지 섹션(이력/포인트/뱃지)은 읽기 전용 — 별도 액션 없음

## 디자인 의도 · 강조점
- 첫 섹션(프로필 편집)이 실제 편집 가능한 유일한 영역 — 나머지는 "내 활동 요약"이라는 위계로 톤 구분
- 뱃지 섹션은 미보유 항목도 함께 보여줌으로써 "수집 동기"를 자극하는 게이미피케이션 의도 — 보유/미보유 대비를 시각적으로 뚜렷하게
- 포인트는 누적치가 가장 중요한 정보이므로 최상단에 크게, 개별 내역은 보조 정보로

## 반응형 · 접근성 노트
- 뱃지/이력 카드 그리드는 모바일 1열, 뱃지는 sm 이상 2열
- 포인트 증감을 색상(초록/빨강)뿐 아니라 부호(+/-)로도 구분(이미 구현) — 유지 필요
- 미보유 뱃지의 grayscale 처리가 저시력 사용자에게도 "미보유" 의미가 전달되도록 텍스트("획득" 표기 여부)로도 구분됨을 유지
