# 공지사항 목록 (회원)

## 페이지 기본 정보

| 항목 | 내용 |
|---|---|
| 라우트 | /notices |
| 접근 권한 | 회원 (`requireProfile`) |
| 한 줄 목적 | 발행된 동아리 공지 목록을 최신순으로 확인하고 상세로 이동한다 |
| 대상 사용자 | 동아리 소식을 확인하려는 회원 |

## 페이지 목적 · 사용자 목표

- 발행된 공지 전체를 최신순으로 훑어본다.
- 관심 있는 공지를 눌러 상세 내용을 본다.

## 정보 구조 (Information Architecture)

1. **페이지 헤더** — "공지사항" + "동아리 소식을 확인해요" 설명
2. **공지 리스트** — 발행된(`published = true`) 공지를 `published_at` 최신순으로 카드 나열. 없으면 빈 상태

## 주요 UI 요소 · 표시 데이터

- **공지 카드** (건별, 클릭 시 `/notices/[id]`로 이동):
  - 제목(`title`)
  - 발행일시(`published_at`, KST 포맷, 값 없으면 빈 문자열)
- **빈 상태**: "등록된 공지가 없어요"

## 상태 (States)

- 발행된 공지 없음 → EmptyState
- 미발행(`published = false`) 공지는 목록에 아예 노출되지 않음(어드민 전용)
- 별도 로딩/에러 상태 UI 없음(서버 렌더링)

## 인터랙션 · 액션

- 카드 클릭 → 해당 공지 상세 페이지로 이동
- 필터/검색/페이지네이션 없음 — 전체 목록을 한 번에 표시

## 디자인 의도 · 강조점

- 목록형 정보 전달이 핵심 — 카드 하나당 제목+날짜만 있는 가벼운 구성이므로, 스캔하기 쉬운 리스트 리듬(간격, hover 피드백)을 살릴 것.
- 최신 공지가 위에 오는 시간순 구조를 시각적으로도 자연스럽게(날짜가 보조 정보로 조용히 배치).

## 반응형 · 접근성 노트

- 카드 전체가 링크이므로 모바일 터치 영역이 충분히 커야 함.
- hover 시 그림자 강조는 마우스 환경 전용 — 터치 환경에서도 클릭 가능함을 시각적으로 인지시킬 것(카드 형태 자체로 clickable 임을 표현).
