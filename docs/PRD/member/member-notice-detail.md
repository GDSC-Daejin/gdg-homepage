# 공지사항 상세 (회원)

## 페이지 기본 정보

| 항목 | 내용 |
|---|---|
| 라우트 | /notices/[id] |
| 접근 권한 | 회원 (`requireProfile`) |
| 한 줄 목적 | 특정 공지의 전체 내용을 읽는다 |
| 대상 사용자 | 공지 목록에서 특정 공지를 클릭해 들어온 회원 |

## 페이지 목적 · 사용자 목표

- 공지 제목·발행일·본문 전체를 읽는다.

## 정보 구조 (Information Architecture)

1. **페이지 헤더** — 공지 제목(`title`)
2. **본문 카드** — 발행일시 + 본문 텍스트

## 주요 UI 요소 · 표시 데이터

- 발행일시(`published_at`, KST 포맷, 없으면 빈 문자열)
- 본문(`body`, 줄바꿈 유지하여 표시)

## 상태 (States)

- 존재하지 않거나 미발행(`published = false`) 공지 id로 접근 시 → `notFound()` (404)
- 그 외 상태 없음(순수 읽기 화면)

## 인터랙션 · 액션

- 읽기 전용 — 별도 액션 없음(뒤로가기는 상단 내비게이션에 의존)

## 디자인 의도 · 강조점

- 콘텐츠 가독성이 최우선 — 본문 줄바꿈·행간·본문 폭을 읽기 좋게.
- 헤더의 제목이 시각적 앵커, 발행일은 보조 정보로 조용히.

## 반응형 · 접근성 노트

- 긴 본문도 모바일에서 줄바꿈이 깨지지 않도록(`whitespace-pre-wrap` 유지 전제하에 폭 대응).
- 텍스트 대비·크기 확보로 가독성 우선.
