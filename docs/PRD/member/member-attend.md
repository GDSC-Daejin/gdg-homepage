# 출석 체크

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /attend (쿼리: event, code) |
| 접근 권한 | 회원 |
| 한 줄 목적 | 진행 중이거나 곧 시작할 이벤트를 골라 출석 코드를 입력하고 출석 처리한다 |
| 대상 사용자 | 이벤트 참석 회원 (QR/링크로 event, code 쿼리를 받아 진입하는 경우 포함) |

## 페이지 목적 · 사용자 목표
- 자신이 참석한 이벤트를 선택한다
- 현장에서 안내받은 출석 코드를 입력해 출석을 인증한다

## 정보 구조 (Information Architecture)
- 좁은 폭 단일 컬럼, 중앙 정렬
- 헤더: "출석 체크" + "이벤트를 선택하고 출석 코드를 입력해주세요"
- 단일 폼: 이벤트 선택 + 코드 입력 + 제출 버튼

## 주요 UI 요소 · 표시 데이터
- 이벤트 선택 드롭다운: 시작 시각이 "현재-24시간" 이후인 이벤트만 노출(과거 오래된 이벤트 제외), 시작일 오름차순
- 출석 코드 입력: 최대 6자, 입력 즉시 대문자로 변환
- URL 쿼리(event, code)로 사전 채움 가능 (예: QR 코드 스캔 시 자동 입력)

## 상태 (States)
- 대상 이벤트가 전혀 없음: "진행 중/다가오는 이벤트가 없어요" 빈 상태, 폼 자체를 숨김
- 이벤트 미선택: 제출 버튼 비활성화
- 제출 중: 버튼 비활성화
- 제출 성공: "출석 처리됐어요" 초록 텍스트
- 제출 실패: 코드 오류 등 에러 텍스트(빨강)

## 인터랙션 · 액션
- 이벤트 선택 변경
- 코드 입력 후 제출 → 서버 검증(RPC) 결과에 따라 성공/실패 인라인 피드백
- 성공 후에도 같은 화면 유지(페이지 이동 없음) — 프로필의 출석 이력에도 반영됨

## 디자인 의도 · 강조점
- 현장에서 빠르게 완료해야 하는 화면 — 불필요한 요소 없이 이벤트 선택→코드 입력→제출의 최소 동선
- 코드 입력은 모바일에서 자주 사용될 것을 고려해 큰 터치 영역과 명확한 성공/실패 피드백이 중요
- QR로 진입 시 이벤트/코드가 이미 채워져 있어 "확인만 누르면 되는" 경험이 되도록 시각적으로도 이미 채워진 상태임을 자연스럽게 보여줄 것

## 반응형 · 접근성 노트
- 모바일 우선 레이아웃 (현장에서 대부분 모바일로 접근)
- 성공/실패를 색상 + 텍스트 메시지 동시 제공(이미 구현, 유지)
