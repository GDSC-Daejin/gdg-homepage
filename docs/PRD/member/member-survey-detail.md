# 설문 상세 · 응답 (회원)

## 페이지 기본 정보

| 항목 | 내용 |
|---|---|
| 라우트 | /surveys/[id] |
| 접근 권한 | 회원 (`requireProfile`) |
| 한 줄 목적 | 설문 문항에 응답을 제출하거나, 이미 응답/마감된 경우 안내를 확인한다 |
| 대상 사용자 | 설문 목록에서 특정 설문을 클릭해 들어온 회원 |

## 페이지 목적 · 사용자 목표

- 설문 문항(평점 또는 서술형)에 답하고 제출한다.
- 이미 응답했거나 설문이 마감된 경우, 왜 응답할 수 없는지 안내를 확인한다.

## 정보 구조 (Information Architecture)

1. **페이지 헤더** — 설문 제목(`title`)
2. **본문 카드** — 세 가지 상태 중 하나만 표시:
   - 이미 응답한 경우: 완료 안내 문구
   - 마감된 설문인 경우: 마감 안내 문구
   - 응답 가능한 경우: 문항별 응답 폼

## 주요 UI 요소 · 표시 데이터

- **문항 목록**(`questions: SurveyQuestion[]`, 각 문항은 `label` + `type`):
  - `type: "rating"` — 1~5점 라디오 버튼 그룹(가로 나열, 각 점수 필수 선택)
  - `type: "text"` — 서술형 textarea(3행)
- 문항 순서는 설문 데이터의 배열 순서 그대로
- 제출 버튼(전체 문항 하단, 1개)

## 상태 (States)

- 존재하지 않는 설문 id → `notFound()` (404)
- 이미 응답 완료(`survey_responses`에 내 응답 존재) → "응답 완료 — 참여해주셔서 감사해요." 안내만 표시, 폼 미노출
- 마감(`is_open = false`, 미응답 상태) → "마감된 설문이에요." 안내만 표시, 폼 미노출
- 응답 가능 → 폼 노출, 제출 처리 중 버튼 disabled
- 제출 실패 → 폼 하단 인라인 에러 텍스트
- 제출 성공 → 페이지 리프레시되어 "응답 완료" 안내 상태로 전환

## 인터랙션 · 액션

- rating 문항: 1~5 중 하나 선택(필수)
- text 문항: 자유 서술(선택, required 아님)
- 제출 → 서버 액션(`submitSurveyResponse`) 호출 → 성공 시 완료 상태로 전환, 실패 시 에러 표시
- 응답은 1인 1회만 가능(재제출/수정 UI 없음)

## 디자인 의도 · 강조점

- 완료/마감 안내는 카드 하나에 짧은 문장으로 끝나는 가벼운 화면 — 과한 강조 없이 담백하게.
- rating 문항의 1~5점 선택은 문항마다 시각적으로 명확히 구분되는 선택지여야 함(현재는 단순 라디오 나열, 점수 척도임을 직관적으로 표현할 여지 있음).
- 여러 문항이 이어지는 폼이므로 문항 간 구분(간격, 구분선)으로 리듬을 줄 것.

## 반응형 · 접근성 노트

- rating 라디오 그룹은 각 옵션에 레이블(점수 텍스트)이 붙어 있어 스크린리더로도 구분 가능 — 좁은 화면에서 가로 나열이 줄바꿈되어도 그룹 관계가 유지되도록.
- textarea는 자유 서술이라 최소 높이 확보, 모바일 키보드 노출 시 레이아웃 밀림 고려.
- 필수 문항(rating) 미입력 시 브라우저 기본 required 검증에 의존 — 에러 메시지 위치가 명확히 보이도록.
