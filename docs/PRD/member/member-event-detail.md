# 행사 상세 (회원)

## 페이지 기본 정보

| 항목 | 내용 |
|---|---|
| 라우트 | /events/[id] |
| 접근 권한 | 회원 (`requireProfile`) |
| 한 줄 목적 | 특정 행사(세션/스터디/데브페스트)의 정보를 확인하고 신청/취소를 처리한다 |
| 대상 사용자 | 행사 목록에서 특정 행사를 골라 들어온 회원 |

## 페이지 목적 · 사용자 목표

- 행사의 일시·장소·발표자·설명·정원 현황을 확인한다.
- 내 신청 상태(미신청/확정/대기)를 확인하고 신청하거나 취소한다.

## 정보 구조 (Information Architecture)

1. **페이지 헤더** — 행사 제목(`title`)
2. **행사 정보 카드** — 유형 배지, 일시, 장소, 발표자, 설명, 신청 인원 현황을 세로로 나열
3. **내 신청 상태 카드** — 좌측에 상태 배지, 우측에 신청/취소 버튼

## 주요 UI 요소 · 표시 데이터

- **유형 배지**: `session`(세션, primary) / `study`(스터디, success) / `devfest`(데브페스트, warning) 톤 구분
- **일시**: `starts_at`을 KST로 포맷해 배지 옆에 표시
- **장소** `location`, **발표자** `speaker`, **설명** `description` — 각 값이 존재할 때만 줄 단위로 표시(없으면 해당 줄 생략)
- **신청 인원**: "신청 N / 정원 M명" — RPC(`event_confirmed_counts`)로 계산한 확정 인원 수. 정원(`capacity`)이 없으면 분모 생략
- **내 신청 상태 카드**:
  - 미신청 — neutral 배지 "미신청" + "신청하기" 버튼
  - 확정 — success 배지 "신청 확정" + "신청 취소" 버튼
  - 대기 — warning 배지 "대기 N번째" (RPC `my_waitlist_position`으로 실시간 순번 계산) + "신청 취소" 버튼

## 상태 (States)

- 존재하지 않는 행사 id → `notFound()` (404)
- 신청/취소 처리 중 버튼 disabled (pending)
- 신청/취소 실패 시 버튼 아래 인라인 에러 텍스트(danger 색)
- 정원 초과 시 신청은 대기(waitlisted)로 전환되는 정책이 이미 반영되어 있음 — 화면상 별도 안내 문구는 없고 상태 배지로만 표현됨

## 인터랙션 · 액션

- "신청하기" 클릭 → 서버 액션으로 등록 처리 → 상태가 확정 또는 대기로 갱신
- "신청 취소" 클릭 → 등록 취소 → 상태가 미신청으로 갱신
- 별도 확인 모달 없이 즉시 실행(낙관적 갱신 아님, 서버 응답 후 리렌더)

## 디자인 의도 · 강조점

- 행사 유형 배지가 첫인상을 좌우하므로 색 대비를 명확히(세션/스터디/데브페스트 톤 구분).
- "신청 인원 N/M명"은 정원 임박 상황을 인지시키는 정보이므로 시각적으로 눈에 띄게.
- 내 신청 상태 카드는 액션 유도 지점 — 상태와 CTA 버튼의 위계를 분명히 하고, 대기 순번처럼 동적으로 바뀌는 숫자는 강조.

## 반응형 · 접근성 노트

- 모바일에서 신청 상태 카드의 좌(상태)/우(버튼) 배치가 좁아지지 않도록 줄바꿈 고려.
- 상태 구분을 색(배지 톤)에만 의존하지 않고 텍스트 레이블("미신청/확정/대기")을 항상 함께 표시.
- 에러 메시지는 텍스트로 노출되어 스크린리더 접근 가능.
