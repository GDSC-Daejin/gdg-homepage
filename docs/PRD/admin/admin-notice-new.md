# 공지 작성 (어드민)

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/notices/new |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 새 공지를 작성해 등록한다 (등록 시점엔 미발행 상태) |
| 대상 사용자 | 공지를 작성하는 운영진 |

## 페이지 목적 · 사용자 목표
- 제목과 본문을 입력해 새 공지를 생성한다
- 생성 후 목록으로 돌아가 후속 작업(발행 등)을 이어간다

## 정보 구조 (Information Architecture)
1. 페이지 헤더("공지 작성")
2. 단일 카드 안에 작성 폼

## 주요 UI 요소 · 표시 데이터
- 제목 입력(필수)
- 본문 textarea(8행, 선택 사항이나 실질적으로 채우는 것이 전제)
- 하단 "생성" 버튼

## 상태 (States)
- 제출 중: 버튼 비활성화
- 제출 실패: 폼 하단 인라인 에러 메시지
- 제출 성공: 목록 페이지(/admin/notices)로 자동 이동

## 인터랙션 · 액션
- 폼 제출 → 성공 시 공지 목록으로 이동(생성된 공지는 미발행 상태로 등록됨, 발행은 상세 화면에서 별도 수행)

## 디자인 의도 · 강조점
- 작성에만 집중하는 단순한 단일 폼 화면 — 산만한 요소 없이
- 이 화면에서 만든 공지는 아직 회원에게 보이지 않는다는 것(미발행)이 사용자에게 은연중 전달되면 좋음
- 제목은 짧고 명확하게, 본문은 여러 줄 작성이 편하도록 충분한 높이 확보

## 반응형 · 접근성 노트
- 좁은 화면에서 폼 카드가 전체 너비를 사용하도록
- textarea는 label과 연결되어야 함(label-for)
