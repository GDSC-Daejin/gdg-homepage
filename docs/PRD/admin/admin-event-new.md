# 어드민 - 이벤트 생성

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/events/new |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 새 이벤트(세션/스터디/데브페스트)를 등록한다 |
| 대상 사용자 | 운영진 |

## 페이지 목적 · 사용자 목표
- 이벤트 기본 정보를 입력해 목록에 새 항목을 추가한다.
- 입력 오류가 있으면 즉시 피드백을 받는다.

## 정보 구조 (Information Architecture)
1. **헤더** — 타이틀 "이벤트 생성"만 표시 (설명/액션 없음)
2. **단일 폼 카드** — 아래 필드 전부를 담은 하나의 폼

## 주요 UI 요소 · 표시 데이터
폼 필드 (전부 하나의 카드 안, 세로 배치):
- **유형** (Select, 필수, 기본값 "세션") — 세션 / 스터디 / 데브페스트
- **제목** (텍스트, 필수)
- **설명** (텍스트, 선택)
- **일시** (DatePicker, 날짜+시간, 필수) — KST 기준 입력, 저장 시 ISO로 변환
- **장소** (텍스트, 선택)
- **발표자** (텍스트, 선택)
- **정원** (숫자, 선택, 최소 1) — 라벨에 "비우면 무제한" 명시
- 하단 제출 버튼: "생성"

## 상태 (States)
- **제출 중**: 버튼 disabled 처리.
- **에러**: 서버 액션 실패 시 폼 하단에 빨간 텍스트로 에러 메시지 표시(필드별 아님, 폼 전체 메시지 1줄).
- **성공**: `/admin/events` 목록으로 이동.

## 인터랙션 · 액션
- 제출 → 서버 액션(createEvent) 호출 → 성공 시 목록으로 리다이렉트, 실패 시 인라인 에러.
- 별도 취소 버튼 없음(뒤로가기로 이탈).

## 디자인 의도 · 강조점
- 단순한 단일 폼 등록 화면. 정보 위계보다 입력 흐름의 매끄러움이 중요.
- 필수/선택 필드 구분이 라벨만으로 드러나야 함(정원 라벨의 부가 설명처럼).
- 유형 선택이 이후 배지 색상과 연결되는 핵심 분류값이라는 점을 고려한 강조 가능.

## 반응형 · 접근성 노트
- 폼이 좁은 화면에서도 한 컬럼으로 자연스럽게 쌓이도록.
- 날짜/시간 입력의 키보드 접근성 확보.
- 에러 메시지는 색상(danger)뿐 아니라 텍스트로 원인을 명시.
