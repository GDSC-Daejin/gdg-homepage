# 어드민 - 이벤트 목록

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/events |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 등록된 세션·스터디·데브페스트를 월별로 훑어보고 신청 현황을 파악한다 |
| 대상 사용자 | 운영진 (이벤트 생성/관리 담당) |

## 페이지 목적 · 사용자 목표
- 전체 이벤트를 최신순으로 확인하고, 특정 월로 좁혀서 볼 수 있다.
- 각 이벤트의 신청 인원(정원 대비)을 한눈에 파악한다.
- 새 이벤트를 만들거나 기존 이벤트 상세로 이동한다.

## 정보 구조 (Information Architecture)
1. **헤더** — 타이틀 "이벤트" + 설명("세션·스터디·데브페스트를 관리해요") + 우측에 월 필터, "이벤트 생성" 버튼
2. **이벤트 카드 리스트** — 시작일시 내림차순, 카드 클릭 시 상세 페이지로 이동

## 주요 UI 요소 · 표시 데이터
- **월 필터(Select)**: "전체" + 데이터에 존재하는 월들(예: "2026년 7월"). 선택 시 쿼리스트링(`?month=`)으로 목록 필터링.
- **이벤트 카드** (클릭 가능한 전체 카드, 링크):
  - 유형 배지 — 세션(primary) / 스터디(success) / 데브페스트(warning)
  - 제목
  - 시작 일시(KST) + 장소(있으면 " · 장소")
  - 우측: "N / 정원 명 신청" — 정원 없으면 "N명 신청"만 표시 (확정자 수 기준, RPC로 집계)

## 상태 (States)
- **빈 상태**: 이벤트가 없으면 "등록된 이벤트가 없어요" 안내만 표시.
- 로딩/에러 상태는 서버 컴포넌트 렌더링으로 별도 UI 없음(현재 구현 기준).

## 인터랙션 · 액션
- 월 필터 변경 → 같은 경로에 `month` 쿼리로 이동, 목록 즉시 갱신.
- "이벤트 생성" 버튼 → `/admin/events/new` 이동.
- 카드 클릭 → `/admin/events/[id]` (수정 페이지)로 이동.

## 디자인 의도 · 강조점
- 리스트형 관리 화면. 유형 배지로 종류를 빠르게 구분하는 것이 핵심.
- "신청 인원/정원" 수치가 운영진에게 가장 중요한 정보이므로 카드 우측에서 눈에 띄게.
- 카드 하나 전체가 클릭 영역이라는 것을 시각적으로 드러낼 것(호버 시 그림자 등).

## 반응형 · 접근성 노트
- 헤더의 필터+버튼 그룹이 좁은 화면에서 줄바꿈될 수 있음을 고려.
- 유형/신청현황을 색(배지 톤)에만 의존하지 않고 텍스트 라벨을 함께 유지.
