# 어드민 회원 관리

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/members |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 전체 회원을 검색·필터링하고, 역할/상태/프로필을 즉시 수정한다 |
| 대상 사용자 | 동아리 운영진(관리자) |

## 페이지 목적 · 사용자 목표
- 이름/학번으로 특정 회원을 빠르게 찾는다.
- 역할(관리자/회원/지원자)·상태(활동/휴면/탈퇴) 조건으로 회원군을 좁혀본다.
- 목록에서 바로 회원의 역할/상태를 바꾸거나 프로필을 수정한다(상세 페이지 이동 없이).

## 정보 구조 (Information Architecture)
1. 페이지 헤더 — "회원 관리" 타이틀 + 설명
2. 필터 카드 — 검색어 + 역할 + 상태 + 검색 버튼 (가로 폼)
3. 회원 목록 테이블 (전체 폭)
4. 행 클릭 시 뜨는 상세 편집 다이얼로그(모달)

## 주요 UI 요소 · 표시 데이터
- **필터 폼**: 검색 입력(이름 또는 학번, placeholder), 역할 셀렉트(전체/관리자/회원/지원자), 상태 셀렉트(전체/활동/휴면/탈퇴), 검색 버튼. 제출 시 쿼리스트링(q, role, status)으로 페이지 이동.
- **회원 테이블 컬럼**: 이름(링크, 상세 페이지로 이동), 학번, 전공, 역할(뱃지), 상태(뱃지: 활동=success, 휴면=neutral, 탈퇴=danger), 가입일.
- **행 클릭** → 다이얼로그 오픈. 다이얼로그 내부:
  - 좌측: 프로필 편집 폼(이름/학번/전공/전화번호/관심 분야[쉼표 구분], 2열 그리드) + "프로필 저장" 버튼 + 저장/에러 피드백.
  - 우측: 현재 역할/상태 뱃지 + 역할 셀렉트 + 상태 셀렉트(변경 즉시 서버 반영) + 에러 메시지.
  - 하단: "상세 페이지로 이동" 링크, "닫기" 버튼.
- 이름 목록 링크와 다이얼로그 내 "상세 페이지로 이동" 링크는 모두 `/admin/members/[id]`로 연결.

## 상태 (States)
- 검색 결과 없음 → "회원이 없어요 / 검색 조건을 확인해보세요" 빈 상태.
- 역할/상태 변경 실패 시 이전 값으로 롤백 + 인라인 에러 메시지(빨간 텍스트).
- 프로필 저장 성공 시 "저장했어요"(성공 텍스트), 실패 시 에러 텍스트.
- 각 변경은 optimistic update(즉시 UI 반영) 후 서버 응답으로 확정/롤백.
- 이름이 빈 회원은 "(이름 없음)"으로 표시.

## 인터랙션 · 액션
- 필터 폼 제출 → URL 쿼리 변경 → 서버에서 재조회.
- 테이블 행 클릭(이름 링크 클릭 제외) → 편집 다이얼로그 오픈.
- 다이얼로그 바깥 클릭 또는 닫기 버튼 → 다이얼로그 닫힘.
- 역할/상태 셀렉트 변경 → 즉시 서버 액션 호출, 실패 시 원복.
- 프로필 폼 제출 → 서버 액션 호출, 성공/실패 피드백.

## 디자인 의도 · 강조점
- 목록에서 바로 처리 가능한 "빠른 편집" 흐름이 핵심 — 다이얼로그가 상세 페이지의 축소판 역할을 하므로 두 화면(목록 다이얼로그, 상세 페이지)의 폼 UI 일관성 유지 필요.
- 역할/상태는 뱃지 컬러로 상태를 한눈에 구분(특히 탈퇴=danger가 시각적으로 눈에 띄어야 함).
- 필터 영역은 보조 기능이므로 목록보다 낮은 위계로.

## 반응형 · 접근성 노트
- 다이얼로그는 2열 그리드(프로필 폼 / 역할·상태)로 구성되어 있어 좁은 화면에서는 1열 스택 전환 고려.
- 테이블은 가로 스크롤 허용.
- 상태 뱃지는 색상 외 텍스트 라벨(활동/휴면/탈퇴)을 항상 동반.
