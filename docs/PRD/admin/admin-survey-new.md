# 어드민 - 설문 생성

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/surveys/new |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 제목과 질문 목록을 구성해 새 설문을 만든다 |
| 대상 사용자 | 운영진 |

## 페이지 목적 · 사용자 목표
- 설문 제목을 정하고, 필요 시 특정 이벤트에 연결한다.
- 평점형/서술형 질문을 자유롭게 추가·삭제·수정하며 설문 구조를 만든다.

## 정보 구조 (Information Architecture)
1. **헤더** — 타이틀 "설문 생성"만
2. **단일 폼 카드**:
   - 기본 정보(제목, 연결 이벤트)
   - 질문 빌더(동적 리스트 + 질문 유형 추가 버튼)
   - 제출 버튼

## 주요 UI 요소 · 표시 데이터
- **제목** (텍스트, 필수)
- **이벤트 연결** (Select, 선택) — "연결 안 함" 기본값 + 전체 이벤트 제목 목록(시작일 내림차순)
- **질문 빌더**:
  - 추가된 질문을 번호(1, 2, ...) + 유형 라벨("평점"/"서술") + 질문 내용 입력창 + "삭제" 버튼으로 한 줄씩 나열
  - 하단에 "평점 질문 추가", "서술 질문 추가" 버튼 2개 — 클릭할 때마다 빈 질문 행이 추가됨
  - 질문이 하나도 없어도 제출 가능한 구조(현재 구현상 질문 필수 검증 없음)
- 제출 버튼: "생성"

## 상태 (States)
- **질문 없음**: 빌더 영역에 추가된 질문 리스트가 비어 있고 안내 문구 없이 추가 버튼만 존재.
- **제출 중**: 버튼 disabled.
- **에러**: 폼 하단 인라인 에러 텍스트.
- **성공**: `/admin/surveys` 목록으로 이동.

## 인터랙션 · 액션
- "평점 질문 추가" / "서술 질문 추가" → 새 질문 행 추가(클라이언트 상태, 즉시 반영).
- 질문 내용 입력 → 해당 질문 label 실시간 업데이트.
- 질문 행의 "삭제" → 해당 질문만 제거.
- 폼 제출 → 질문 배열을 JSON으로 직렬화해 서버 액션 호출, 성공 시 목록 이동.

## 디자인 의도 · 강조점
- 이 페이지의 핵심은 "질문 빌더"라는 동적 리스트 편집 경험 — 추가/삭제/순서(번호)가 직관적으로 보여야 함.
- 평점형과 서술형이 결과 페이지에서 다르게 집계되므로(평점=분포 그래프, 서술=텍스트 나열), 생성 단계에서부터 유형 구분이 시각적으로 뚜렷해야 함.
- 이벤트 연결은 부가 정보이므로 제목/질문 빌더보다 위계를 낮춤.

## 반응형 · 접근성 노트
- 질문 행(번호+유형+입력+삭제)이 좁은 화면에서 줄바꿈되어도 각 요소가 무엇인지 식별 가능해야 함.
- 질문 유형은 텍스트 라벨("평점"/"서술")로 이미 표기되어 색 의존 없음.
