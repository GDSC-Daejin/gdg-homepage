# 예산/후원 관리 (어드민)

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/budget |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 동아리 수입·지출 내역과 스폰서 후원 내역을 기록·조회한다 |
| 대상 사용자 | 예산을 관리하는 운영진 |

## 페이지 목적 · 사용자 목표
- 수입/지출 내역을 빠르게 추가하고 전체 재정 상태(총수입/총지출/잔액)를 한눈에 확인한다
- 시즌별 스폰서(후원) 내역을 기록·조회한다
- 잘못 입력한 내역/스폰서를 삭제한다

## 정보 구조 (Information Architecture)
한 페이지에 두 개의 독립된 섹션이 위아래로 배치된다.

1. **예산 섹션**
   - 상단: 통계 카드 3개 (총 수입 / 총 지출 / 잔액)
   - 내역 추가 폼 (카드)
   - 내역 목록 테이블 (최신 날짜순)
2. **스폰서 섹션**
   - 섹션 헤더
   - 스폰서 추가 폼 (카드)
   - 스폰서 목록 테이블 (최신 등록순)

## 주요 UI 요소 · 표시 데이터
- **통계 카드**: 총 수입, 총 지출, 잔액 — 원화(₩) 포맷, 콤마 구분
- **내역 추가 폼**: 날짜(날짜선택기), 구분(수입/지출 셀렉트, 기본값 수입), 분류(텍스트), 금액(숫자, 1 이상), 메모(선택)
- **내역 테이블**: 날짜 / 구분(수입·지출) / 분류 / 금액(지출은 강조색으로 구분) / 메모(없으면 "-") / 삭제 버튼
- **스폰서 추가 폼**: 이름, 금액(숫자, 1 이상), 시즌(선택), 메모(선택)
- **스폰서 테이블**: 이름 / 금액 / 시즌(없으면 "-") / 메모(없으면 "-") / 삭제 버튼

## 상태 (States)
- 내역/스폰서가 하나도 없을 때: 각각 별도의 빈 상태("등록된 내역이 없어요" / "등록된 스폰서가 없어요")
- 폼 제출 중: 버튼 비활성화
- 폼 제출 실패: 폼 하단에 인라인 에러 메시지
- 폼 제출 성공: 폼 초기화, 목록에 즉시 반영

## 인터랙션 · 액션
- 내역/스폰서 추가: 폼 제출 → 성공 시 입력값 초기화, 테이블에 새 행 추가
- 삭제: 각 행의 삭제 버튼 클릭 → 브라우저 confirm("삭제할까요? 되돌릴 수 없어요") → 확인 시 삭제, 실패 시 해당 행 옆에 에러 메시지
- 지출 금액은 목록에서 시각적으로 구분되어 보임(강조색)

## 디자인 의도 · 강조점
- 재정 현황(총수입/총지출/잔액)이 페이지 진입 시 가장 먼저 눈에 들어와야 함 — 상단 통계 강조
- 예산/스폰서 두 섹션은 명확히 구분되되 같은 톤의 하나의 관리 페이지로 느껴지게
- 지출 항목은 색으로 구분(위험/경고 계열), 수입은 중립 톤
- 입력 폼은 관리자가 반복적으로 빠르게 채워 넣는 작업 흐름을 고려해 인라인/한 줄 배치 선호

## 반응형 · 접근성 노트
- 통계 카드 3개는 좁은 화면에서 세로로 쌓임
- 테이블은 좁은 화면에서 가로 스크롤 필요
- 색상만으로 수입/지출을 구분하지 않고 텍스트 라벨("수입"/"지출") 병행
