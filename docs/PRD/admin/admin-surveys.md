# 어드민 - 설문 목록

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/surveys |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 생성된 설문을 관리하고(열기/닫기/삭제) 응답 결과로 이동한다 |
| 대상 사용자 | 운영진 |

## 페이지 목적 · 사용자 목표
- 전체 설문 목록과 각 설문의 응답 건수, 열림/닫힘 상태를 확인한다.
- 설문을 열거나 닫아 응답 접수를 제어한다.
- 결과 페이지로 이동하거나 설문을 삭제한다.

## 정보 구조 (Information Architecture)
1. **헤더** — 타이틀 "설문" + 설명("설문을 생성하고 응답 결과를 확인해요") + 우측 "설문 생성" 버튼
2. **설문 카드 리스트** — 생성일 내림차순

## 주요 UI 요소 · 표시 데이터
- **설문 카드** (한 줄, 좌/우 분할):
  - 좌측: 상태 배지(열림=success / 닫힘=neutral) + 제목(링크, 클릭 시 결과 페이지 이동) + "응답 N건"
  - 우측: "열기/닫기" 토글 버튼, "삭제" 버튼

## 상태 (States)
- **빈 상태**: "등록된 설문이 없어요".
- **토글/삭제 중**: 각 버튼 disabled, 실패 시 버튼 아래 인라인 에러.
- 삭제는 confirm 대화상자("설문을 삭제할까요? 되돌릴 수 없어요.") 통과 후 진행.

## 인터랙션 · 액션
- 제목 클릭 → `/admin/surveys/[id]/results` 이동.
- "설문 생성" → `/admin/surveys/new` 이동.
- "열기/닫기" → 상태 토글, 성공 시 같은 페이지 새로고침(목록 이동 없음).
- "삭제" → confirm 후 삭제, 성공 시 새로고침.

## 디자인 의도 · 강조점
- 목록의 핵심 정보는 "지금 응답을 받고 있는가(열림/닫힘)"와 "응답이 얼마나 쌓였는가"이므로 이 둘이 가장 먼저 읽혀야 함.
- 제목 링크와 우측 액션 버튼들의 클릭 영역이 명확히 분리되어야 함(카드 자체는 링크가 아님, 이벤트 목록과 다름).

## 반응형 · 접근성 노트
- 우측 버튼 그룹(열기/닫기, 삭제)이 좁은 화면에서 줄바꿈되어도 카드 레이아웃이 깨지지 않도록.
- 상태는 배지 색상뿐 아니라 "열림/닫힘" 텍스트로 표기되어 있음 — 유지 필요.
