# 포인트/뱃지 관리 (어드민)

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/points |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 회원에게 포인트를 부여하고 뱃지를 만들어 수여한다 |
| 대상 사용자 | 활동 보상을 관리하는 운영진 |

## 페이지 목적 · 사용자 목표
- 특정 회원에게 포인트를 부여(또는 차감)하고 사유·관련 이벤트를 남긴다
- 특정 회원에게 뱃지를 수여한다
- 뱃지 종류를 새로 만들거나 삭제한다
- 최근 포인트 지급/차감 내역을 확인한다

## 정보 구조 (Information Architecture)
위→아래 4개 블록:
1. 포인트 부여 폼 / 뱃지 수여 폼 — 2단 카드 (넓은 화면에서 좌우 배치)
2. 뱃지 관리 — 뱃지 생성 폼 + 등록된 뱃지 목록
3. 최근 포인트 로그 테이블

## 주요 UI 요소 · 표시 데이터
- **포인트 부여 폼**: 회원 선택(이름 · 학번), 포인트(양수/음수 입력 가능, 차감은 음수), 사유(텍스트), 이벤트 연결(선택, 드롭다운)
- **뱃지 수여 폼**: 회원 선택, 뱃지 선택(아이콘 + 이름)
- **뱃지 관리**: 생성 폼(이모지 기본값 🏅, 이름, 설명) + 뱃지 카드 목록(아이콘, 이름, 설명, 삭제 버튼)
- **최근 포인트 로그 테이블**(최대 50건): 회원 이름(탈퇴 시 "(탈퇴)") / 포인트(양수는 성공색 "+n", 음수는 위험색) / 사유 / 일시

## 상태 (States)
- 뱃지 없음: 빈 상태("등록된 뱃지가 없어요")
- 포인트 로그 없음: 빈 상태("포인트 내역이 없어요")
- 각 폼 제출 중: 버튼 비활성화
- 각 폼 제출 성공: 폼 하단에 성공 메시지("포인트를 부여했어요" / "수여했어요") 노출
- 각 폼 제출 실패: 인라인 에러 메시지

## 인터랙션 · 액션
- 포인트 부여/뱃지 수여: 제출 → 성공 메시지 또는 에러 메시지 인라인 표시(페이지 리로드 없음, 로그 테이블은 갱신되지 않을 수 있음에 유의)
- 뱃지 생성: 제출 → 목록에 새 뱃지 추가
- 뱃지 삭제: confirm 확인 후 삭제

## 디자인 의도 · 강조점
- "부여/수여" 두 폼은 관리자가 가장 자주 쓰는 핵심 액션이므로 최상단에 나란히 배치해 접근성 강조
- 포인트 증감은 색으로 즉각 구분되어야 함(양수=성공색, 음수=위험색)
- 뱃지는 이모지 아이콘이 시각적 정체성을 가지므로 목록에서 아이콘이 두드러지게
- 로그 테이블은 보조 정보이므로 하단에 위치, 참고용 톤

## 반응형 · 접근성 노트
- 포인트/뱃지 폼 2단 배치는 좁은 화면에서 1단으로 전환
- 로그 테이블은 좁은 화면에서 가로 스크롤
- 포인트 증감 색상에 텍스트 부호(+/-)를 병행해 색맹 사용자도 구분 가능하게 유지
