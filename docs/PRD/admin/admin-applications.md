# 어드민 지원서 심사

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/applications |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 시즌별 지원서를 상태별로 필터링해 확인하고 합격/불합격을 판정한다 |
| 대상 사용자 | 동아리 운영진(관리자) |

## 페이지 목적 · 사용자 목표
- 특정 시즌의 지원서를 상태(전체/심사 중/합격/불합격)별로 훑어본다.
- 지원자의 자기소개·지원 동기·관심 분야 답변을 읽고 합격/불합격을 결정한다.

## 정보 구조 (Information Architecture)
1. 페이지 헤더 — "지원서 심사" 타이틀 + 현재 시즌명(설명)
2. 컨트롤 바 — 상태 탭(전체/심사 중/합격/불합격) + 시즌 셀렉트 (좌우 배치)
3. 지원서 카드 리스트 (세로 스택, 카드당 1건)

## 주요 UI 요소 · 표시 데이터
- **상태 탭**: 전체/심사 중/합격/불합격 — 링크 기반 탭, 현재 선택된 탭은 primary 배경으로 강조.
- **시즌 셀렉트**: 지원서가 존재하는 시즌 목록(내림차순) 중 선택. 변경 시 해당 시즌+현재 상태로 이동.
- **지원서 카드** (건당):
  - 지원자 이름 + 학번 · 전공 (한 줄)
  - 상태 뱃지: 심사 중(warning) / 합격(success) / 불합격(danger)
  - 답변 목록(정의 리스트): 자기소개, 지원 동기, 관심 분야 — 각각 줄바꿈 보존해서 표시.
  - 우측 상단: 심사 버튼(심사 중 상태일 때만 노출) — 합격(primary) / 불합격(danger).

## 상태 (States)
- 해당 조건에 지원서 없음 → "지원서가 없어요 / 선택한 조건에 해당하는 지원서가 없어요" 빈 상태.
- 지원자 프로필을 찾을 수 없으면 "알 수 없음" 표시.
- 심사 처리 중 버튼 비활성화, 실패 시 카드 하단에 에러 텍스트.
- 심사 완료된 지원서(합격/불합격)는 버튼이 사라지고 뱃지만 남음(재심사 불가 UI).

## 인터랙션 · 액션
- 상태 탭 클릭 → 시즌 유지한 채 상태만 바꿔 이동.
- 시즌 셀렉트 변경 → 상태 유지한 채 시즌만 바꿔 이동.
- 합격/불합격 버튼 클릭 → 확인창(confirm) 노출 → 확인 시 서버 액션 호출 → 성공 시 뱃지·버튼 갱신, 실패 시 에러 표시.

## 디자인 의도 · 강조점
- 카드형 리스트는 "읽고 판단하는" 흐름에 맞춰 텍스트 가독성이 최우선 — 답변 3종(자기소개/동기/관심분야)이 스캔하기 쉽게 구획되어야 함.
- 심사 버튼(합격/불합격)은 되돌리기 어려운 결정이므로 확인 절차가 있다는 점을 시각적으로도 암시(예: 강조된 위치, 명확한 색 대비)하면 좋음.
- 상태 탭은 필터 UI이자 현재 심사 진행 상황(전체 대비 심사 중 비율)을 암시하는 자리이기도 함 — 탭에 건수 표시를 고려할 수 있음(현재 미구현).

## 반응형 · 접근성 노트
- 카드 내부 "이름 + 상단 액션 버튼" 가로 배치는 좁은 화면에서 줄바꿈 필요.
- 상태는 뱃지 색상과 텍스트 라벨을 함께 사용해 색맹 사용자도 구분 가능.
- 자기소개/동기 등 장문 답변은 `white-space: pre-wrap`으로 원본 줄바꿈 유지 — 디자인도 이 점 고려.
