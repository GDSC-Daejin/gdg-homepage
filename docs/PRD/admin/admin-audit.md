# 어드민 감사 로그

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/audit |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 관리자들이 수행한 주요 작업 이력을 최근순으로 열람한다 |
| 대상 사용자 | 동아리 운영진(관리자) |

## 페이지 목적 · 사용자 목표
- 누가 언제 어떤 관리 작업(역할 변경, 지원서 심사, 포인트 부여 등)을 했는지 추적한다.
- 문제 발생 시 원인이 된 작업을 되짚어본다.

## 정보 구조 (Information Architecture)
1. 페이지 헤더 — "감사 로그" 타이틀 + "관리자 작업 내역 최근 100건" 설명
2. 감사 로그 테이블 (전체 폭, 최신순, 단일 화면 — 페이지네이션 없음)

## 주요 UI 요소 · 표시 데이터
- **테이블 컬럼**: 시각(KST), 행위자(관리자 이름, 없으면 "(알 수 없음)"), 작업(한글 라벨 — 역할 변경/상태 변경/지원서 심사/출석 코드 발급/문의 답변/포인트 부여/뱃지 수여, 매핑 없는 값은 원본 문자열), 대상(target 문자열, 없으면 "-"), 상세(detail JSON을 문자열로 그대로 표시).
- 최근 100건으로 고정(추가 로드/페이지네이션 없음).
- 필터/검색 UI 없음.

## 상태 (States)
- 로그 없음 → "감사 로그가 없어요" 빈 상태.
- "상세" 컬럼은 원시 JSON 문자열(JSON.stringify) 그대로 노출 — 가공되지 않은 디버그성 데이터.

## 인터랙션 · 액션
- 순수 조회 전용 페이지. 클릭/필터/액션 요소 없음.

## 디자인 의도 · 강조점
- 감사 로그는 신뢰성과 스캔 용이성이 핵심 — 시각·행위자·작업 3요소가 한눈에 읽혀야 함.
- "상세" 컬럼의 원시 JSON은 현재 가장 가공되지 않은 부분 — 필요하면 가독성 있는 포맷(키-값 나열 등)으로 개선할 여지가 있는 지점으로 표시해둘 것(단, 현재 동작은 JSON 문자열 그대로).
- 작업 종류가 다양하므로(역할 변경/지원서 심사/포인트 부여 등) 작업 컬럼에 유형별 구분(아이콘/색) 없이 텍스트 라벨만 존재 — 시각적 구분을 강화할 여지 있음.

## 반응형 · 접근성 노트
- 테이블 가로 스크롤 허용.
- "상세" 컬럼의 긴 JSON 문자열이 좁은 화면에서 줄바꿈되거나 잘리지 않도록 고려 필요.
