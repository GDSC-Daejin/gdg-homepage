# 어드민 회원 상세

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/members/[id] |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 특정 회원 한 명의 프로필·역할·상태·출석 이력을 자세히 보고 수정한다 |
| 대상 사용자 | 동아리 운영진(관리자) |

## 페이지 목적 · 사용자 목표
- 회원 개인의 상세 프로필 정보를 확인하고 수정한다.
- 해당 회원의 역할/상태를 변경한다.
- 회원의 전체 출석 이력을 이벤트별로 확인한다.

## 정보 구조 (Information Architecture)
1. 페이지 헤더 — 회원 이름(타이틀) + 학번(설명)
2. 프로필 카드 — 가입일 + 프로필 편집 폼 + 역할/상태 편집 폼(같은 카드 내 구분선으로 분리)
3. 출석 기록 카드 — 이벤트별 출석 이력 테이블

## 주요 UI 요소 · 표시 데이터
- **헤더**: 이름(없으면 "(이름 없음)"), 학번.
- **프로필 카드 상단**: 가입일(KST 포맷).
- **프로필 편집 폼**: 이름/학번/전공/전화번호(2열 그리드) + 관심 분야(쉼표 구분, 전체 폭) + "저장" 버튼 + 저장/에러 피드백.
- **역할·상태 폼** (구분선 아래): 현재 역할 뱃지 + 상태 뱃지, 역할 셀렉트(관리자/회원/지원자), 상태 셀렉트(활동/휴면/탈퇴). 변경 시 즉시 반영.
- **출석 기록 테이블**: 이벤트 제목, 이벤트 일시(KST), 출석 체크 시각(KST). 최신순 정렬.

## 상태 (States)
- 존재하지 않는 회원 id → 404(notFound).
- 출석 기록 없음 → "출석 기록이 없어요" 빈 상태.
- 프로필 저장 성공/실패 인라인 피드백(성공 텍스트/에러 텍스트).
- 역할/상태 변경 실패 시 이전 값으로 롤백 + 에러 메시지.
- 이벤트가 삭제된 출석 기록은 "-"로 표시.

## 인터랙션 · 액션
- 프로필 폼 제출 → 서버 액션으로 프로필 필드 업데이트.
- 역할/상태 셀렉트 변경 → 즉시 서버 액션 호출(확인 다이얼로그 없음).
- 이 페이지에는 뒤로가기/목록 링크가 명시적으로 없음 — 사이드바 내비게이션으로 이동.

## 디자인 의도 · 강조점
- 회원 관리 목록(admin-members)의 편집 다이얼로그와 사실상 동일한 폼 구성 — 두 화면의 폼 레이아웃·톤을 통일해 "같은 기능의 확장판"임을 시각적으로 보여줄 것.
- 프로필 정보(정적 데이터)와 역할/상태(운영 판단이 개입되는 데이터)를 한 카드 안에서도 구분선으로 시각적으로 분리해 중요도 차이를 표현.
- 출석 기록은 이 회원의 "활동 이력" 증거이므로 별도 카드로 명확히 분리.

## 반응형 · 접근성 노트
- 프로필 폼의 2열 그리드는 좁은 화면에서 1열로 전환 고려.
- 역할/상태 셀렉트는 폭이 고정(가로 정렬)되어 있어 모바일에서는 줄바꿈 허용 필요.
- 출석 테이블 가로 스크롤 허용.
