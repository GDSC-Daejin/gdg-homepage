# 어드민 - 이벤트 상세/수정

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/events/[id] |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 이벤트 정보를 수정하고, 신청자·출석 현황을 관리하며 출석 코드를 발급한다 |
| 대상 사용자 | 운영진 (특히 행사 당일 출석 체크 담당) |

## 페이지 목적 · 사용자 목표
- 이벤트 정보(제목/일시/장소 등)를 수정한다.
- 신청자 명단과 확정/대기 상태, 실제 출석 여부를 확인한다.
- 출석 체크용 코드를 발급하고 QR로 공유한다.
- 필요 시 이벤트를 삭제한다.

## 정보 구조 (Information Architecture)
1. **헤더** — 타이틀 "이벤트 수정" + 우측 "삭제" 버튼
2. **수정 폼 카드** — EventForm 재사용(생성 폼과 동일 필드, 값 채워진 상태)
3. **출석 현황 카드** — 확정 대비 출석 인원, 현재 발급된 코드, 코드 발급/재발급 버튼, QR 코드(코드가 있을 때)
4. **신청자 목록 테이블 카드** — 이름/학번/상태/출석 여부

## 주요 UI 요소 · 표시 데이터
- **수정 폼**: 유형/제목/설명/일시/장소/발표자/정원 — 생성 폼과 동일, 기존 값이 채워짐. 제출 버튼 라벨 "수정".
- **출석 현황 카드**:
  - "출석 현황" 라벨 + "출석 인원 / 확정 인원" 숫자 (예: 12 / 20)
  - "현재 코드" — 발급된 코드(monospace, 굵게) 또는 "미발급"
  - 코드 발급 버튼 — 미발급 시 "코드 발급", 이미 있으면 "코드 재발급"
  - 코드가 있으면 QR 이미지(160x160) + 출석 URL 텍스트(`/attend?event=..&code=..`)
- **신청자 목록 테이블**: 컬럼 = 이름 / 학번 / 상태(배지: 확정=success, 대기=neutral) / 출석(배지 "출석" 또는 "-")
  - 이름/학번 없으면 "(이름 없음)" / "-" 표시

## 상태 (States)
- **신청자 없음**: 테이블 영역에 "신청자가 없어요" 빈 상태.
- **코드 미발급**: QR/URL 영역 미표시, "미발급" 텍스트만.
- **폼 제출 중 / 삭제 확인**: 삭제는 브라우저 confirm 대화상자("이벤트를 삭제할까요? 되돌릴 수 없어요.") 후 진행.
- **에러**: 수정 실패, 코드 발급 실패, 삭제 실패 각각 해당 액션 영역 하단에 인라인 에러 텍스트.

## 인터랙션 · 액션
- 폼 수정 후 제출 → 같은 페이지 새로고침(router.refresh), 목록 이동 없음.
- "삭제" → confirm 통과 시 삭제, 성공하면 이벤트 목록으로 이동.
- "코드 발급/재발급" → 새 코드 발급, 페이지 새로고침되어 QR·코드 갱신.
- 신청자 테이블은 읽기 전용(현재 구현상 상태 변경 액션 없음).

## 디자인 의도 · 강조점
- 한 페이지 안에 "편집"과 "운영(출석)"이라는 두 성격의 작업이 공존 — 시각적으로 구획을 명확히 분리(수정 폼 / 출석 운영 영역).
- 행사 당일 빠르게 참조할 "출석 인원/확정 인원" 숫자와 QR 코드가 가장 눈에 잘 띄어야 함.
- 삭제는 되돌릴 수 없는 파괴적 액션이므로 시각적으로 격리(danger 톤, 헤더 우측 단독 배치).

## 반응형 · 접근성 노트
- QR 이미지와 URL은 행사장에서 모바일로도 볼 수 있어야 하므로 모바일 폭에서도 잘림 없이 표시.
- 테이블은 좁은 화면에서 가로 스크롤 허용.
- 상태 배지는 색+텍스트 병행으로 색맹 사용자도 구분 가능하게.
