# 문의/건의 관리 (어드민)

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /admin/inquiries |
| 접근 권한 | 어드민 |
| 한 줄 목적 | 회원이 남긴 문의를 상태별로 확인하고 답변한다 |
| 대상 사용자 | 문의 응대를 담당하는 운영진 |

## 페이지 목적 · 사용자 목표
- 접수된 문의를 상태(전체/접수/답변완료)별로 필터링해 확인한다
- 미답변 문의에 답변을 작성해 등록한다
- 이미 답변한 문의의 질문·답변 내용을 다시 확인한다

## 정보 구조 (Information Architecture)
1. 페이지 헤더
2. 상태 필터 탭 (전체 / 접수 / 답변완료) — URL 쿼리(`?status=`)와 연동
3. 문의 카드 리스트 (최신순), 카드마다:
   - 제목 + 작성자 · 작성일시
   - 상태 배지
   - 문의 본문
   - 답변완료: 답변 내용 + 답변일시 표시
   - 접수(미답변): 답변 작성 폼 인라인 노출

## 주요 UI 요소 · 표시 데이터
- 상태 탭: 전체 / 접수 / 답변완료 (선택된 탭 강조 스타일)
- 문의 카드: 제목, 작성자 이름(없으면 "알 수 없음"), 작성일시, 상태 배지("접수"=경고톤, "답변완료"=성공톤), 본문 전문(줄바꿈 유지)
- 답변완료 카드: 회색 배경 박스에 답변 텍스트 + 답변일시
- 미답변 카드: 답변 textarea + "답변 등록" 버튼

## 상태 (States)
- 선택한 필터에 해당하는 문의가 없을 때: 빈 상태("문의가 없어요 · 선택한 조건에 해당하는 문의가 없어요")
- 답변 폼 제출 중: 버튼 비활성화
- 답변 폼 제출 실패: 폼 하단 인라인 에러
- 답변 등록 성공: 해당 카드가 답변완료 상태로 전환(배지·본문 표시 변경)

## 인터랙션 · 액션
- 상태 탭 클릭 → 해당 상태로 필터링된 목록으로 이동(URL 변경)
- 답변 작성 → 제출 → 성공 시 카드가 답변완료 카드로 전환되고 답변 폼은 사라짐

## 디자인 의도 · 강조점
- 미답변(접수) 문의가 우선적으로 눈에 띄어야 함 — 상태 배지 색 대비 강조
- 문의-답변은 하나의 대화 흐름처럼 카드 안에서 위(질문)-아래(답변) 구조로 자연스럽게 읽히게
- 필터 탭은 가벼운 토글 형태로, 현재 선택 상태가 명확히 구분되어야 함

## 반응형 · 접근성 노트
- 좁은 화면에서 카드 상단의 제목/배지 영역이 줄바꿈되어도 배지가 잘리지 않게
- 상태는 배지 색상 + 텍스트 라벨을 함께 사용(색상 단독 의존 금지)
- 답변 textarea는 라벨과 명확히 연결(label-for)
