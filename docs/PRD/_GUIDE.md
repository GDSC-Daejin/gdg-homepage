# PRD 작성 가이드 (클로드 디자인 전달용)

이 폴더의 PRD는 **이미 구현된 페이지를 클로드 디자인에게 재설계·디자인 개선 목적으로 전달**하기 위한 문서다.
클로드 디자인은 우리 디자인 시스템과 코드베이스를 이미 알고 있다. 따라서:

- 코드 구현 방법·기술 스택·컴포넌트 이름을 다시 설명하지 않는다.
- "무엇을 보여주고, 왜 필요하고, 어떤 상태·흐름이 있는지" 즉 **화면의 의도와 정보 구조**에 집중한다.
- 각 페이지 = 마크다운 파일 1개. 파일명은 라우트 기반 kebab-case (예: `member-dashboard.md`, `admin-members.md`).

## 두 가지 페이지 유형

### A. 공개 랜딩성 페이지 (about, events, projects, team, login)
`~/jieunsse/dev/plan/docs/새모듈/AI 라이트업.md` 의 섹션형 콘텐츠 스펙 양식을 따른다.
(Hero / 문제공감 / 소개 / 핵심 / CTA 등 — 해당 페이지에 맞는 섹션만 취사선택)

### B. 앱 페이지 (로그인 후 회원/어드민 영역: 폼·테이블·대시보드)
랜딩 섹션 양식 대신 아래 **앱 페이지 스켈레톤**을 따른다.

```
# <페이지 이름>

## 페이지 기본 정보
| 항목 | 내용 |
|---|---|
| 라우트 | /... |
| 접근 권한 | 비로그인 / 회원 / 어드민 |
| 한 줄 목적 | ... |
| 대상 사용자 | ... |

## 페이지 목적 · 사용자 목표
- 이 페이지에서 사용자가 이루려는 것 1~3개

## 정보 구조 (Information Architecture)
- 화면을 위→아래로 어떤 영역/섹션으로 나누는지, 각 영역이 담는 내용

## 주요 UI 요소 · 표시 데이터
- 목록/카드/폼/필터/버튼 등과 각각이 보여주는 실제 데이터 필드

## 상태 (States)
- 빈 상태 / 로딩 / 에러 / 권한 없음 / 성공 피드백 등 화면이 가져야 할 상태

## 인터랙션 · 액션
- 사용자가 할 수 있는 동작과 결과(제출/필터/이동/삭제 등), 확인·검증 흐름

## 디자인 의도 · 강조점
- 클로드 디자인에게 주는 방향: 무엇을 시각적으로 강조할지, 위계, 톤

## 반응형 · 접근성 노트
- 모바일 고려사항, 폼 접근성, 상태 표시 색 의존 회피 등
```

## 원칙
- 실제 코드를 읽고 **현재 구현된 데이터·필드·동작을 근거로** 작성한다 (상상하지 않는다).
- 간결하게. 페이지당 A4 1~2장 분량. 불필요한 미사여구 금지.
- 한국어로 작성.
