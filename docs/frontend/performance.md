# 프론트엔드 성능 관리

성능 최적화는 실제 병목이나 명시된 목표가 있을 때만 검토한다. 보안·접근성·데이터 정확성·동작 보존이 우선이다.

## 변경별 검토

- 데이터 요청 순서가 바뀌면 앞 요청 결과가 필요 없는 작업을 불필요하게 직렬 대기하지 않는지 확인한다.
- Server → Client props가 바뀌면 실제 소비 필드와 RSC 응답 크기를 확인한다.
- 에디터·차트·대형 라이브러리를 추가하거나 import 경로를 바꾸면 초기 bundle 포함 여부를 확인한다.
- props/state로 계산 가능한 값을 Effect와 별도 state로 복제하지 않는다.
- 콜백에서만 필요한 상태 때문에 불필요한 렌더 구독을 만들지 않는다.
- 부모 렌더마다 새 컴포넌트 타입을 정의해 입력값·포커스·상태를 잃지 않는지 확인한다.

이 규칙은 변경부와 관련 호출·소비 코드에만 적용한다. 일괄 memoization, 모든 요청의 캐시 도입, 모든 컴포넌트의 dynamic 전환, 기계적인 barrel import 금지는 하지 않는다.

## 측정

성능 개선을 주장하려면 같은 화면·데이터·브라우저·빌드 조건에서 전후 수치를 비교한다. Lighthouse는 변경 범위에 초기 로드 성능 목표가 있을 때만 현재 설치된 도구로 실행한다. 한 번의 점수 차이만으로 성능 저하를 단정하지 않는다.

선택한 규칙은 문제 없음, 수정 대상, 개선 후보, 미검증, 적용 외 중 하나로 기록한다. 이 검토는 타입 검사·테스트·빌드를 대체하지 않는다.
