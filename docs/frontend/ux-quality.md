# 프론트엔드 UX 품질 기준

모든 항목을 모든 화면에 적용하지 않는다. 변경된 사용자 행동과 관련된 항목만 선택하고, 나머지는 적용 외로 둔다.

## MUST

- 진입점, 정상 완료, 실패·취소 경로를 정의한다.
- 핵심 행동을 의미 있는 버튼·링크·입력으로 제공한다.
- 사용자가 기다리는 실제 구간에 로딩 상태를 제공한다.
- 로딩·성공·빈 결과·오류 상태를 필요한 화면에서 구분한다.
- 오류에는 원인, 영향, 재시도 또는 수정 방법을 제공한다.
- 처리 중인 행동의 중복 실행을 막는다.
- 의미에 맞는 HTML, 접근 가능한 이름, 키보드 조작, 보이는 포커스를 제공한다.
- 색상만으로 오류나 상태 변화를 전달하지 않는다.
- 요구된 이동·입력 보존·뒤로가기 동작을 검증한다.

## DEFAULT

- 기존 src/components의 공용 UI를 재사용한다.
- 중요한 주 행동을 명확히 한다.
- 저장·삭제·업로드에는 처리 중과 완료 피드백을 제공한다.
- 내부 이동은 next/link, 서버 우선과 최소 Client 경계를 따른다.
- URL 공유·새로고침·뒤로가기로 복원해야 하는 검색·필터·정렬·페이지 상태는 URL에 표현한다.
- 목록에서 상세로 이동한 뒤 돌아올 때 요구된 조건과 위치를 보존한다.
- 모바일·데스크톱에서 핵심 플로우와 긴 텍스트·빈 상태·오류 상태를 확인한다.

## 기능별 인수 조건

사용자 목표, 진입점, 정상 플로우, 완료 상태, 실패·취소·재시도, 로딩·빈 결과·오류, 뒤로가기, URL 상태, 키보드·포커스, 반응형 범위, 검증 방법을 변경 범위에 맞게 선택한다.

검증하지 못한 행동은 통과가 아니라 미검증으로 기록한다.
