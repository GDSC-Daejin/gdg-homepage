# React 컴포넌트 합성 규칙

컴포넌트에 설정용 boolean prop을 계속 추가하기보다, 실제 UI 조합이 복잡해질 때 children·명시적 슬롯·별도 컴포넌트를 검토한다.

## 기본 원칙

- 단순한 시각 상태나 접근성 속성은 명확한 boolean prop으로 둘 수 있다.
- 서로 다른 업무 의미가 boolean 조합에 숨으면 variant를 명시하거나 별도 컴포넌트로 분리한다.
- 한 컴포넌트에서만 쓰는 상태를 Context나 전역 store로 올리지 않는다.
- 상태는 소비하는 가장 가까운 곳에 둔다.
- 새 추상화는 실제 중복·상태 공유·복잡도를 줄일 때만 추가한다.
- 컴포넌트 이름이나 파일 분리 자체를 목표로 삼지 않는다.

## 검토 질문

- 새 prop이 두 개 이상의 UI 조합을 표현하고 있는가?
- children이나 명시적 하위 컴포넌트가 의도를 더 잘 드러내는가?
- 공유 상태가 실제로 필요한가?
- 이 추상화가 현재 문제를 줄이는가?

입력·상태 보존·키보드 동작·포커스는 docs/frontend/ux-quality.md의 기준으로 검증한다.
