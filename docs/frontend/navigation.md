# Next.js 내비게이션 규칙

App Router의 client-side transition과 기본 prefetch를 사용하되, 실제 사용자 행동·대기·상태 보존을 기준으로 판단한다.

## 링크

- 앱 내부 경로는 next/link를 우선한다.
- 외부 URL과 파일 다운로드는 일반 a를 사용한다.
- 큰 테이블·무한 스크롤·링크가 매우 많은 목록은 prefetch={false}를 검토한다.
- 링크를 임의의 버튼과 router.push로 바꾸지 않는다. 조건부 이동이나 실제 이벤트 처리일 때만 프로그래밍 방식 이동을 사용한다.

## 로딩과 동적 경로

- 사용자가 기다리는 서버 요청에는 필요한 범위의 loading.tsx 또는 Suspense를 제공한다.
- 동적 경로라는 이유만으로 loading UI를 추가하지 않는다.
- 사용자별·요청별 데이터는 런타임 동작을 유지한다. 빌드 시 미리 알 수 있는 정적 경로만 generateStaticParams를 검토한다.
- 로딩 중 입력값과 draft가 사라지지 않는지 확인한다.
- 전환이 실제로 느릴 때만 useLinkStatus나 progress UI를 검토한다.
- sticky header가 이동 후 콘텐츠를 가리지 않도록 필요한 경우 scroll-padding-top을 사용한다.

## 검수

- 내부 링크의 실제 이동과 히스토리 동작을 확인한다.
- 대기가 발생하는 이동은 로딩 상태를 확인한다.
- 목록·상세·폼의 요구된 검색·필터·입력 상태 보존을 확인한다.
- 느린 전환이나 초기 로드 성능이 변경 범위에 포함된 경우에만 Lighthouse를 실행한다.
